# 「あつまれ、あれこれ」棚全体の構想

このドキュメントは、アプリ全体の構造と、今後追加していくカセット（ゲーム）の全体像をまとめたものです。**個別のゲームを実装する前に、必ずここを読んで全体の位置づけを確認してください。**

関連ドキュメント：
- `あれそれどれこれ_プロジェクト概要.md` … 技術構成・デプロイ・開発方針
- `脱出ミッション設計.md` … 脱出ミッションの詳細設計
- `爆弾解除設計.md` … 爆弾解除カセットの詳細設計（クイズ解除／実物解除／同時解除）

---

## 基本構造：3階層

```
棚（トップ画面）
└── カセット          … 1本のゲーム。棚に並ぶ
    └── ゲーム        … カセット内の遊び方。複数あれば選択画面が出る
        └── モード    … ゲーム内のバリエーション
              ↓
         オプション    … 掛け合わせで変わる設定
```

**重要な原則**：**中身が1つしかない階層は自動でスキップする。** 例えば「あれそれどれこれ」カセットは中にゲームが1つしかないので、ゲーム選択画面を飛ばして直接モード選択へ行きます。階層は柔軟に持ちつつ、無駄なタップを増やさないためです。

### 分けるか、まとめるかの判断基準

- **単体でルール説明が成立する** → 独立したカセットにする（時限爆弾、オークションなど）
- **単体だと5分で終わる小品** → まとめる（しりとり・ニョッキ・にらめっこ → むかしあそび）
- **核が同じで、どちらか一方しか選べない** → まとめる（ワードウルフと通常人狼 → 人狼ゲーム）
- **同時に成立するもの** → モードではなくオプションにする（掛け算になると破綻するため）

## 棚の段（ジャンル）

段は増やして構いません。**4段に収める必要はなく、10段でも良い**という方針です。カセットが増えたら段も足してください。

| 段 | 性格 |
|---|---|
| ことばであそぶ | 言葉で伝える・当てる |
| あてる・こたえる | 出題に答える |
| かけひき | 賭ける・読み合う |
| はやさきそい | 速さ・反射神経 |
| だましあい | 正体を隠す |
| きょうりょく | 全員で1つの目標に向かう |
| からだをうごかす | 体を使う |
| みんなのこと | 相手を知る |

**注意**：現在の実装では段は3つ（ことばであそぶ／かけひき／からだをうごかす）です。カセットが増えるのに合わせて拡張してください。「ぜんぶ」の段は、カセットが少ないうちは重複感が強いため削除済み。増えて探しにくくなったら復活させます。

## カセット一覧

### 🎴 あれそれどれこれ ★実装済み
言葉で説明して当てる。このプロジェクトの原点。

**オプション**：出題方法（人間／AI読み上げ／AI一言ヒント／**ジェスチャー**※未実装）× 封印ワード（なし／あり／即アウト）× 脱落ルール

### 🐺 人狼ゲーム
- **ワードウルフ** … 実装済み（非表示中）。1人だけ違うお題。関連ペア30組
- **通常の人狼** … 未実装。役職の量でモード分け
  - **カジュアル**（村人と人狼だけ）
  - **ノーマル**（占い師・霊媒師・騎士を追加）※標準
  - **スペシャル**（狂人・共有者・妖狐なども）

**方針**：ゲームマスターを不要にする。役職配布・夜の行動・投票集計をすべてアプリが行い、誰も真実を知らないまま進行できるようにする。

### 🎎 むかしあそび
昔からある遊びを、アプリの力で進化させる。**ルール説明が要らない**のが最大の強み。

- しりとり進化版（条件つき。重複を音声認識で自動チェック）
- たけのこニョッキ（被ったらアウト。音声認識と相性が良い）
- あっち向いてホイ（まず上下左右ボタンの簡易版。顔向き検知は後から）
- にらめっこ（**声の検知＋人間の最終判断**）
- お題にらめっこ（表情認識。認識の厳しさで難易度調整）
- 音声認識伝言ゲーム（**認識の不正確さをあえて崩れる原因にする**）

**進化のさせ方は3種類**：①審判・進行役をアプリが引き受ける ②見えないものを見えるようにする ③制約を足す

### 💣 爆弾解除 ★実装済み（クイズ解除のみ）
- **クイズ解除** … 実装済み。AIの説明を聞いて3択、ライフ制。心拍音がミスするほど速くなる
  - **通常版** … 協力プレイ。1台のスマホ（手渡し）でも、全員スマホ（1人1台・盤面を全員で共有）でも遊べる
  - **競争版** … 1人1台・部屋が必須。同じコードに全員で同時挑戦。並び順は各自別々、ミスはライフ−1と残り時間−10秒
- **実物解除** … 未実装。Keep Talking and Nobody Explodes式（判定ルールは完全オリジナル）。9種のセンサーモジュール
- **同時解除** … 未実装。2チーム以上に分かれて同時に解除する協力型・競争型

詳細は `爆弾解除設計.md` を参照。**クイズ解除が完全に検証されてから実物解除に着手する**方針です。
いま遊べる中身（クイズ）に合わせて「ことばであそぶ」の段に置いていますが、
実物解除が入ったら「からだをうごかす」へ移します。

### 👑 クイズ王決定戦 ★実装済み（非表示中）
難易度を選んで挑戦。高難度ほど高得点。

### 🍟 ロシアンポテチ
引くか、**他人に押し付けるか**を選ぶ。押し付けられた人はお題に答えれば回避できる形も検討。時限爆弾と似すぎないよう「押し付け」を軸にする。

### 💰 オークションバトル ★実装済み（非表示中）
チップを賭ける。順位別の強制ベット率、アイテム4種。

### 🤥 ハッタリゲーム / 🎲 チキンレース
かけひき系。詳細は未設計。

### 🥊 早押しトーナメント ★実装済み（非表示中）
1対1のブラケット。**「AI出題」と「人が出題」を切り替えられるようにする**（現状はスマホを2人の間に置くのにお題が見えてしまう矛盾がある）。

### ⚡ 反射神経テスト / 🧠 連想リレー
はやさきそい系。連想リレーは音声認識で「もう出た言葉」を自動チェックできるので審判が要らない。

### 🤝 〇〇を知ろう
相手をどれだけ知っているかを競う。

- **A 本人当て** … 「一番早起きなのは誰？」の形。**数値で聞けば正解が自動で定まる**
- **B あの人の答えを予想** … 本人が先に入力、他が予想
- **C 誰の答えでしょう** … 全員の答えをシャッフルして当てる

**必須の配慮**：質問に**「踏み込み度」**を持たせる（🟢かるい／🟡ふつう／🔴ふみこむ）。遊ぶ前に全員でどこまで踏み込むか決められるようにする。**誰かが悲しくなるゲームにしない。**

### 🚨 脱出ミッション
協力ゲーム。詳細は `脱出ミッション設計.md` を参照。

### 📡 通信ミッション
1人だけがマニュアルを見て、他の人が操作する。互いに相手の画面が見えないのが肝。

### 🎨 みんなで一枚絵
ガーティックフォン式。全員で少しずつ描き足して1枚を完成させる。競争が一切ない。

### 🧩 スマホ合体パズル
複数のスマホを並べて1つの絵・文字・地図を作る。**このアプリでしか成立しない遊び**。1人だけ違う絵を持つ「間違い探し人狼」などの派生も。

### 🏃 からだをうごかす系
- だるまさんがころんだ（全員分の端末が必要）
- サイレント鬼ごっこ（自分のスマホが自分の声を監視し、声を出すとバレる）
- ケイドロ電波探知（鬼に距離が表示される）
- 逃走中
- 椅子取りゲーム（**自作音楽ができてから**）
- スマホでかくれんぼ（スマホ自体を隠す。QRで確保）
- ARかくれんぼ（隠れ場所の写真＋絵を、カメラ映像に半透明で重ねて探す）

### ⚔️ たいけつ
1対1のフィジカル勝負。

- **手押し相撲** … 加速度センサーで崩れを検知。**スマホは持たずポケットか腕に固定**（手のひらで押し合う競技のため）。体格差が出るので相手を選ぶ
- **スマホチャンバラ** … スイッチスポーツ式。振る速度＝攻撃、横向き＝ガード。**手首ストラップ必須**（振ったスマホが飛ぶ危険）
- **早撃ち** … ランダムなタイミングの合図に最速で反応。**フライングは即負け**。2人以上でも可
- **バランス対決** … 片足立ちでスマホを持ち、揺れが少ない人が勝ち。**体格差が出にくく誰とでも遊べる**

### 🔫 リアルFPS（最終目標）
QRコードを身につけ、カメラの照準で読み取って命中。射程5〜10m、紙を貼る手間、画面を見ながら走る危険性が課題。土台とノウハウが溜まってから。

## 全ゲーム共通で必ず守ること

### 1. 体を動かす系は、全員の同意を取る

**一度同意すれば、プレイヤーが変わるまで（名前の変更・人数の増減）再度聞かない。** ただし**メンバーが変われば体力も体調も変わる**ので、そこでは聞き直します。

同意画面には以下を明記：
- どんな動作があるか（振る／走る など）
- 周りに人や物がないか確認を促す
- スマホの固定（ストラップ等）の案内
- けが・体調に不安がある人は無理をしないこと

**さらに「参加しない」を選べるようにする。** その人は見学・進行役に回れる形にして、断る気まずさをなくします。

#### 同意を求める範囲の線引き（重要）

**同意画面は「身体的なリスクがあるもの」に限定します。全ゲームに一律で出してはいけません。**

理由：同意画面が多いと**読まれなくなり、本当に大事な警告まで読み飛ばされます。** 体を動かす系の「周りに人や物がないか確認」はケガに直結するので、そこが埋もれるのが最も危険です。

| 種類 | 対応 |
|---|---|
| **身体的リスク**（体を動かす系、身体を使う罰） | **事前に同意を取る** |
| **心理的な配慮**（人狼で人間関係がこじれる等） | **同意ではなく、設計とフォローで解決する** |

心理的なものに事前警告を出しても、**プレイヤーにできることが何もありません。** 「人間関係が傷つくかも」と言われても対処のしようがないためです。代わりに下記の仕組みで対応します。

#### 心理的な配慮の実装方法

**① 選択肢として提示する**
「〇〇を知ろう」の**踏み込み度（🟢かるい／🟡ふつう／🔴ふみこむ）**が良い例です。遊ぶ前に全員でどこまで踏み込むか決められる。**同意を取るより自然な形の配慮**になります。

**② MVP（称号）を配る**
ゲーム終了時に、アプリが勝手に称号を付ける。「一番鋭かった人」「一番騙された人」「一番惜しかった人」など。

- **説教でもフォローでもなく、単に褒めるだけ**なので白けない
- **負けた側にも何かつく**ので、勝ち負け以外の話題ができる
- 空気を戻すというより、**そもそも空気が悪くならない**方向に効く
- **人狼に限らず全ゲームで使える**ため、共通の仕組みとして作る価値がある

> なお「これはゲームです」といった注意書きを出す案は**採用しません。** 説明的すぎて白けさせる可能性の方が高いためです。

### 2. ルールの伝え方を軽視しない

**伝え方が悪いと、意図した遊び方・面白さから変わってしまいます。**「わからない・面白くない」を避けるため、必ず以下を行ってください。

- **ゲーム/ミッション開始前にセットアップ画面を挟む**（いきなり始めない）
- **禁止事項は赤字で強調**する（「他の人の画面は絶対に見ないでください」など）
- **「準備OK」を押すまで始まらない**（全員が読む時間を作る）
- **プレイ中も禁止事項を画面の隅に小さく出し続ける**（途中で忘れるため）
- **初回は詳しく、2回目以降は簡潔に**（既存のモード説明の仕組みを流用）

### 3. 罰ゲームは慎重に

身体能力を求める罰（スクワット等）は、**全員が同意した場合のみ出現**させる。さらに**他人にバレずに拒否できる**設定を用意する（全員の前で「無理です」と言うこと自体がつらいため）。

**推奨は身体を使わない罰**：次のミッションで発言禁止／ヒントが見られない／持ち時間が減る、など。特に「発言禁止」は協力ゲームでチーム全体に効くので面白い。

### 4. 詰みを構造的に防ぐ

人数・環境によってクリア不可能になる状況を、**設計段階で潰す**こと。詳細は脱出ミッション設計を参照。

## リアルタイム同期の土台について

**以下のゲームは、複数端末のリアルタイム同期（WebSocket等）が前提です。**

人狼／だるまさんがころんだ／サイレント鬼ごっこ／ケイドロ／逃走中／スマホでかくれんぼ／ARかくれんぼ／スマホ合体パズル／音声録画伝言／もうどっち向いてホイ／脱出ミッション／通信ミッション／みんなで一枚絵／スマホチャンバラ／早撃ち

**10本以上がこの土台を待っている状態**です。棚の実装が終わったら、**次はこの土台を作るのが最優先候補**になります。1つ作れば一気に多数が実装可能になります。

**さらに、大人数対応（クラス全員で遊ぶ状況）もこの土台に依存します。** 全員が自分のスマホで同時に参加できるようになるため、「1台を回す形式」で生じる待ち時間の問題が根本から解消されます。詳細は後述の「プレイ人数への対応」を参照してください。

**部屋への参加方式（確定済み）**：部屋を立てる人だけアカウント必須。他は**部屋コード＋名前入力だけ**で参加。「集まってすぐ遊ぶ」という性格に合わせています。

## プレイ人数への対応

### 基本方針：カセットを増やすのではなく、棚の見え方を変える

**「大人数用カセット」は作りません。** 「24人でも遊べる」というくくりには遊びとしての共通点がなく、棚のジャンル分け（遊びの性格で分ける）の基準が壊れるためです。また、そのカセットは少人数のとき丸ごとグレーアウトされ、棚が虫食いになります。

代わりに、**アプリが現在の人数を知っていることを利用して、棚の見え方を変えます。**

- 遊べるカセットを前に出す／目立たせる
- 人数が足りないカセットは薄く表示し、「◯人以上必要です」と明示する
- 例：24人 → 大人数向けが前に来る／2人 → ⚔️たいけつ（1対1）が前に来る

**カセットの数は変えず、並び方だけが変わる。** これなら棚の構造を壊しません。

### 人数ごとの想定

| 人数 | 対応 |
|---|---|
| 1人 | 遊べない（警告） |
| 2〜3人 | 遊べるが「4人以上推奨」と表示 |
| **4〜8人** | **最適**。現在の設計そのまま |
| 9〜12人 | 遊べるが「テンポが落ちます」と警告。チーム戦を勧める |
| 13人以上 | チーム戦のみ（個人戦は選べないようにする） |

**あれそれどれこれの8人上限は、元の物理カードの設計に由来するものです。** 上限自体は撤廃してよいですが、**単に上げるだけでは体験が壊れます。** 「1人が説明して他が当てる」形式のため、24人だと自分の出番まで23回待つことになり、ほぼ全員がただ見ているだけになります。

### 大人数（クラス全員など）への対応

**クラス全員で遊ぶ状況は現実的な想定として扱います。**

**困るのは「1台のスマホを回す」形式だけです。**

- **1台を回す形式** → 待ち時間が人数に比例して増える（あれそれどれこれ、オークションなど）
- **全員が同時に動く形式** → **人数が増えても待ち時間ゼロ**（拍手、鬼ごっこ、人狼、合体パズルなど）

したがって：

**① リアルタイム同期の土台ができれば、大人数問題はほぼ自動的に解決します。** 全員が自分のスマホで同時に参加できるようになるためです。

**② 24人でもそのまま成立する（むしろ人数が多いほど良い）ゲーム**
- 👏 拍手系・🤫 静寂系 … 24人で揃うか、24人全員が黙れるか。**難易度も盛り上がりも上がる**
- 🎨 みんなで一枚絵 … カオスさが増して面白くなる方向
- 🧩 スマホ合体パズル … 24台並べると壮観。**むしろ大人数向き**
- 🐺 人狼 … 元々大人数のゲーム。24人なら人狼5〜6人
- 🏃 だるまさんがころんだ／逃走中／サイレント鬼ごっこ … **元々クラス全員でやる遊び**
- 🍟 ロシアンポテチ … 人数が多いほど誰に回るか読めない

**③ 1台を回す形式にはチーム戦を用意する**
- 24人 → 4人×6チーム、または6人×4チーム
- 各チームが同時に、別々に遊ぶ。スマホはチームごとに1台（現在の1台完結の設計がそのまま使える）
- 最後にチーム同士のスコアを比べる
- **待ち時間が4分の1以下**になり、チーム内で相談する楽しさも生まれる
- ※各チームのスコアをまとめるためリアルタイム同期が必要

## 食わず嫌い対策（知らないゲームが選ばれない問題）

棚に20本並んでも、**結局いつもの1〜2本しか遊ばれない**という問題が起こり得ます。準備中のカセットが多いうちは、選択肢がさらに狭く見えます。

対策（優先度順）：

1. **人数からの絞り込み** … 上記の仕組みをそのまま使う。**押し付けがましくなく、選択肢が減ること自体が選びやすさになる**ため最も効果的
2. **🎲 おまかせボタン** … 棚に置く。ランダムで1本選ばれる。決められないときの救済
3. **今日のおすすめ** … 日替わりで1本を大きめに表示
4. **プレイ後の提案** … 「次はこれもどう？」と似た系統を**1本だけ**提案する（多いと押し付けになる）

## 今後の進め方

**1つのゲームを完璧にしてから次へ進む。** 中途半端なものを並べないこと。過去に5モードを一気に作った結果、「お題が丸見え」「スマホを渡す時間がない」といった矛盾が大量に発生しました。

準備中のカセットは「？」で表示し、**中身が決まっているものだけ名前を出す**（期待を持たせるため）。
