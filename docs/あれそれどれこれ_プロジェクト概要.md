# 「あれそれどれこれ」プロジェクト概要

このドキュメントは、Claude Codeなど別セッションのAIアシスタントに、このプロジェクトの背景を過不足なく伝えるためのものです。実装タスクの詳細は別ファイル「実装タスクリスト.md」を参照してください。

## これは何のプロジェクトか

「あれそれどれこれ」は、くまくん（開発者）が学校の課題として作った、こそあど言葉のダジャレをタイトルにしたアナログパーティーゲームです。絵カードを並べて、出題者が名前を言わずに特徴を説明し、他のプレイヤーが当てる、というカルタ形式が基本ルールです。

このゲームのスマホ用デジタル companion アプリを開発しています。元は物理カードの補助アプリでしたが、現在は複数のミニゲームモードを持つ本格的なパーティーゲームアプリに成長しています。

## 技術構成

### フロントエンド
- **単一のHTMLファイル**（`aresoredorekore.html`）。HTML/CSS/JavaScriptがすべて1ファイルに収まっている
- フレームワーク不使用のバニラJS。IIFE（`(function(){ ... })();`）でラップされている
- スマホ縦画面（幅460px程度）を前提にしたレイアウト
- フォント：Shippori Mincho（見出し）、Zen Maru Gothic（本文）、DotGothic16（数字・スコア表示）
- 画面遷移は「スクリーンベースのステートマシン」方式：`<div class="screen" id="scr-xxx">` が並んでいて、`goTo(id)` 関数が `.active` クラスの付け替えで画面を切り替える。画面ごとに `enterXxx()` という初期化関数があり、`goTo()` の中でIDに応じて呼び分けている

### バックエンド
- **ConoHa VPS**（メモリ1GBプラン、Ubuntu 24.04）上で稼働
- Node.js + Express + better-sqlite3（SQLite）
- pm2で常時起動、Discord Bot（別プロジェクト）とプロセスを共存させている
- ドメイン：`https://aresoredorekore.duckdns.org/`（DuckDNSの無料サブドメイン、Let's Encryptで証明書取得済み、Nginxでリバースプロキシ）
- Express側は `public/index.html` としてフロントエンドのHTMLファイルをそのまま静的配信している（つまりフロントとバックエンドは同じオリジン、同じドメインから配信される一体型構成）

### 認証・データモデル
- ホスト1人だけがアカウントでログインする方式（`username`/`password`、bcryptjsでハッシュ化、express-sessionでセッション管理）
- プレイヤー（友達）はログイン不要、名前を入力するだけ
- お題データベース：デフォルト110件＋ホストが追加したカスタムお題、`topics` テーブルで管理
- 対戦履歴：`matches` テーブルに `player_names` / `rounds`（JSON） / `final_scores`（JSON） / `started_at` / `ended_at` を保存

### AI機能（Gemini API）
- 一部モード（AI読み上げ・時限爆弾・クイズ王決定戦・オークションバトル）で、お題の説明文をAIに生成させている
- 使っているのは **Google Gemini API**（`gemini-2.0-flash`）。理由：クレジットカード登録なしで無料枠が使える（開発者が学生でクレカを持っていないため）
- バックエンドに `POST /api/ai-describe` エンドポイントがあり、`{name, ng_words}` を渡すと `{description}` が返る
- サーバーの `.env` に `GEMINI_API_KEY` を設定する必要がある（`https://aistudio.google.com` で発行）

## デプロイ運用上の重要な注意点（詰まりやすいポイント）

- **自宅回線からVPSのSSH（22番ポート）に到達できない**問題が発生中。原因未特定（ConoHa側ではなく自宅回線側の可能性が高い）
- 現状の回避策：ConoHaのブラウザコンソール（VNC）から入り、一時的にSSHを443番ポートに移動させてからPowerShellで`scp -P 443`する、という手順を毎回行っている（Ubuntu 24.04は`ssh.socket`管理なので`sshd_config`の`Port`変更は効かず、systemdソケットユニットの上書きが必要）
- 恒久対策として `sslh`（1つのポートでSSHとHTTPSを自動振り分けするツール）の導入が未着手のまま残っている
- ConoHaのセキュリティグループは新規作成に失敗する状態で、既存の `default` / `IPv4v6-SSH` / `IPv4v6-Web` しか使えない
- **デプロイのたびにダウンロードフォルダに同名ファイルが増えていく問題が実際に発生した**（`aresoredorekore.html`, `aresoredorekore_1.html`, `_2.html`...）。過去に「古いファイルを間違って転送してしまう」事故が起きている。ファイル名に日付やバージョンを含める、あるいはbase64サイズやgrepでの中身確認を徹底することを推奨

## アプリの画面構成（screen state machine）

主要な画面ID（`goTo('scr-xxx')` で遷移）：

```
scr-splash      → スタート画面
scr-login       → ログイン/新規登録
scr-setup       → プレイヤー人数・名前入力
scr-mode        → モード選択（+ タイマー・ハンデ・出題者・各モード専用設定）
scr-mode-rules  → 初回のみ表示されるルール説明画面
scr-ready       → 長押しでスタート画面
scr-countdown   → 3・2・1カウントダウン
scr-play        → 通常のお題出題画面（timer + topic-card + 正解/不正解/反則ボタン）
scr-reveal      → ラウンド結果発表
scr-score       → スコア画面（もう一度/モードを選び直す/終了）
```

モード別の専用画面（通常のscr-playを使わないモード用）：

```
scr-wolf-pass, scr-wolf-gather, scr-wolf-result   → ワードウルフ
scr-bomb-play, scr-bomb-end                       → 時限爆弾
scr-quiz-turn                                     → クイズ王決定戦
scr-tourney-match, scr-tourney-champion           → 早押しトーナメント
scr-auction-bid, scr-auction-question, scr-auction-result → オークションバトル
```

## 現在実装済みのモード一覧（`MODES` 配列、9個）

| id | 名前 | 概要 |
|---|---|---|
| normal | 通常プレイ | 3分ラウンド、出題者が説明、正解ボタンでフルスクリーンピッカーが開き誰が正解したか選ぶ |
| seal | 封印ワード | 通常プレイ＋お題ごとの禁止ワード自動表示 |
| speed | 秒でこれ | 1分のスピードラウンド（※削除予定、後述） |
| outstrict | 一発アウト | 禁止ワードを言ったら即アウト・次のお題へ自動送り |
| oneword | ひとことで、あれ | 説明は一言だけ（※改編予定、後述） |
| ai | AI読み上げ | 出題者なし、AIが説明文を生成しTTS（`speechSynthesis`）で読み上げ。お題名は画面非表示 |
| wordwolf | ワードウルフ | 1人だけ違うお題を渡され、自由議論→スマホ手渡しで投票→少数派を当てる。複数ラウンド制、通算スコア |
| bomb | 時限爆弾 | 難易度別（🟢かんたん/🟡ふつう/🟠むずかしい/🔴ナニソレシラナイ/🟣むりなんだが）のコード（お題）を、AIの説明文+3択で解除。ライフ3つ制、協力プレイ |
| quizking | クイズ王決定戦 | ターン制、自分で難易度を選んで挑戦（配点1〜8点）、AIの説明文+3択 |
| buzzer | 早押しトーナメント | 1vs1のシングルエリミネーション、先に3ポイント取った方が勝ち上がり |
| auction | オークションバトル | チップ制の賭けゲーム、6ラウンド、難易度×倍率でチップが増減、アイテム4種、順位に応じた強制ベット率 |

これらのモードのうち、`bomb` / `quizking` / `auction` は共通のクイズバンク（`QUIZ_BANK` オブジェクト、5つの難易度キーごとに `{name, yomi, ng_words}` の配列）を参照している。**この`QUIZ_BANK`は、サーバーから取得している110件のお題DBとは完全に別の、フロントエンド内にハードコードされたデータ**である点に注意（後述の実装タスクで統合予定）。

## 既知の技術的パターン（新規実装時に踏襲すべきもの）

- `api(path, opts)` — fetchのラッパー関数。`credentials:'include'`、JSON自動変換、エラー時は `.error` フィールドをメッセージとして例外化する
- `play` オブジェクト — 現在進行中のラウンド・ゲームの一時状態を持つグローバル変数。モードごとに `play.wolfXxx` / `play.bombXxx` / `play.auctionXxx` のようにプレフィックスを付けて名前空間を分けている
- `state` オブジェクト — アプリ全体の永続的な状態（プレイヤー一覧、選択中のモード、認証情報など）
- `scorePlayer(id, delta)` — プレイヤーのスコアを加算する共通関数（ハンデ倍率も内部で処理）
- `logRound(modeId, scoreDeltas)` — ラウンド結果をバックエンドの対戦記録に送信する共通関数
- 各モードのUIは `.pk-btn`（フルスクリーン選択肢ボタン）、`.hp-chip`（ピル型トグルチップ）、`.reveal-row` / `.reveal-list`（結果一覧の行）など、既存のCSSクラスを使い回している
