**この文書は第38弾のものです。**第31弾までの記録は末尾に残してある。

## なぜ、もう一度作り直したのか

第31弾版を実際に遊んで「面白くない」と判定した。原因ははっきりしていた。

**いま出ている1品しか見えなかった。**

オークションの面白さは「これに賭けるか、次を待つか」を見比べて悩むところにある。
1品ずつ順に出して、それが終わるまで次が見えない形だと、
悩む材料が「この品を買うか買わないか」しかない。
比べる相手がいないので、値付けの根拠が自分の勘だけになり、
結局は運ゲーに落ちる。

第38弾の答えは単純で、**6品を最初から全部ならべた**。
開場の画面がこのリメイクの象徴で、他のすべてはここから出ている。

## 芯は「相場」

同じ系統（🏺壺もの／🖼絵もの／💎光もの）の品が売れるたび、
**その系統の相場が1つ上がる**。得点は「品質の値 × 売れた時の相場」。

これで何が起きるか：

- みんなが群がっている系統は、相場が育つぶん**高くつく**（競り合いで値も上がる）
- 誰も見ていない系統は**安く買えて、自分で相場を育てられる**
- だから「人気の品を追う」以外の勝ち筋が、毎回ちゃんと存在する

数の上でも成り立つことを tests/auction-logic.js が固定している——
3人で1系統に群がるより、ひとりで放置された系統を3つ買い集めた方が高い（20点 対 12点）。

### 系統は、毎ラウンド必ず2品ずつ出す

無作為に6品選ぶと「絵もの4・光もの2・壺もの0」のような回が出る。
そうなると壺ものの相場は一度も動かず、**「放っておかれた系統を買う」という
芯の戦略が、その回には存在しない**。得点計算のバグではなく、
遊びの根幹が偶然によって消える種類の欠陥なので、系統ごとに2品ずつに固定した。

## 1ラウンドの流れ

| 段階 | 画面 | やること |
|---|---|---|
| 開場（下見） | `scr-rt-au-open` | 6品が全部ならぶ。見比べて、口で探り合う |
| アイテム | `scr-rt-au-power` | 3種から1つだけ選ぶ |
| 競り | `scr-rt-au-bid` | 1品ずつ競る。残りの品は下に見え続ける |
| 値踏み | `scr-rt-au-guess` | 落札しなかった人が品質を予想する |
| 開示 | `scr-rt-au-reveal` | 予想 → 品質 → 相場 → 得点 の順に出す |
| 結果 | `scr-rt-au-result` | 順位と、点の内訳 |

**1画面につき、やることは1つ。**第31弾は1枚の画面が中身を差し替えていたが、
段階ごとに「いま何をする時間なのか」が読み取りづらかった。

### 段階ヒント

品物は「見た目」の一言だけで出て、競りが進むと12秒ごとに1本ずつヒントが開く。
**時間で決める**（入札の回数ではなく）。回数で決めると、放送の届く順で
端末ごとにヒントの数がずれ、「全員が同じものを見ている」が壊れる。

ヒントは品質ごとに別の文が書いてある（`auction-items.js` の `q.fine/plain/fake`）。
「ヒントと品質が矛盾しない」ことを、あとから検査するのではなく
**データの形で保証している**。

## 決めごと（迷った時にここへ戻る）

1. **落札できなかった人は、何も失わない。** 強制入札のような足枷は入れない
2. **落札できなかった人にも、毎回することがある。** それが値踏み予想
   （当たれば+1枚、外しても何も失わない）
3. **最初に値をつけた人にごほうび**（+2枚）。情報がいちばん少ない時に
   飛び込む理由をつくる。1品につき1人だけ
4. **誰も入札しない品は、すぐには流さない。** 全員が「見送る」を押して初めて流れ、
   流れた品は次の品のあとにもう一度だけ出る
5. **残ったチップも点になる**（3枚で1点）。ただし貯め込みが勝たない値にしてある——
   26枚抱えて8点より、育った相場で上物1つ（12点）が勝つ
6. **ラウンドが変わると、相場は1に戻る。** 前のラウンドの熱を持ち越さない

### 持ち時間

**「最初の持ち時間」と「延長」は別の数。**ここを1つにしていた時期があり、
延長の8秒が開始の持ち時間としても使われていた。
ヒントは12秒ごとに開くので、**誰も入札しない品ではヒントが1本も開かないまま流れていた**。

さらに、延長が12秒より短いと「早い時点で1人が入札した品」も
ヒントが開く前に閉じる。**情報ゼロのまま落札が成立する品**ができると、
この遊びの核（全員が同じ情報を見た上でのタイミング勝負）が、
その品だけ成り立たない。タイミング勝負が成立するのは、
情報という土俵が全員に同じだけ用意されている時だけ。

そこで `OPEN_EXTEND_SEC`(14) > `HINT_STEP_SEC`(12) を約束にした。
この大小関係は tests/auction-logic.js が**振る舞いで**固定している
（数の比較ではなく「閉じる時点でヒントが何本開いているか」で書いてある。
持ち時間を縮めても、ヒントの間隔を延ばしても赤くなる）。

## アイテム（3種・ラウンドごとに1つだけ）

| | できること |
|---|---|
| 🔍 鑑定眼 | 好きな1品の品質を、**自分だけが**知る |
| 🎟 半額チケット | 落札できたら、支払いが半分になる（端数は切り上げ） |
| 📣 相場操作 | 好きな系統の相場を、落札せずに+1する |

ぜんぶは持てない。**選ぶこと自体が戦略**になっている。
選ばなかった人には、いちばん素直なもの（鑑定眼）が自動で配られる——
「選ばなかったから何も無い」だと、席を外していた人が一方的に不利になる。

鑑定眼で見た品は、**その端末の棚にだけ**正体が出る。
出さないと「使ったのに何も起きない」になる（落とし穴21）。

## 秘密の扱い（大切なこと1・落とし穴6）

|                          | 本人 | 他 | 大画面 | 公開スナップショット |
|--------------------------|:---:|:--:|:-----:|:---:|
| 品質                     | ✕  | ✕ |  ✕   | ✕（鑑定眼で見た品だけ本人に） |
| 秘密入札の額（締切前）   | ○  | ✕ |  ✕   | ✕ |
| 値踏み予想（開示前）     | ○  | ✕ |  ✕   | ✕ |
| 相場・内訳の宣言・開いたヒント | ○ | ○ | ○ | ○ |

見張り方は**2層**にしてある：

1. 公開スナップショットを**文字列にして、品質の言葉と正体の文を全部探す**
2. 端末に届く `privateFor` にも、他人のぶんが混ざっていないかを見る

「載せていないつもり」を信じずに、届いたものをバラして探す形。
実際にサーバーが品質を漏らすよう壊すと、画面側のテストと
realtime-auction の両方が赤くなることを確認してある。

## 数字の置き場所

**遊びの数字は `public/js/auction-logic.js` の `RULES` に全部ある。**
画面にも進行役にも書き写さない。目安時間の計算（`estimateMinutes`）も
ここに置いてあるので、持ち時間を1つ変えれば棚も設定画面も自動で追いつく。

設定画面で決められるのは**ラウンド数と下見の長さの2つだけ**。
つまみの上限・下限もここから入れる。
かつては「はじめのチップ」「締め切りの長さ」「最下位への救済」も出していたが、
どれもルール層に無く、**決めても効かない設定**になっていた（落とし穴21）。

## テスト

| ファイル | 見ているもの |
|---|---|
| `tests/auction-items.js` | 品物プール（30品）。ヒントが品質と矛盾しないこと |
| `tests/auction-logic.js` | 得点・相場・順位・持ち時間の約束 |
| `tests/realtime-auction.js` | 実サーバー＋socket.ioで開場から決着まで。**秘密が最優先** |
| `tests/rt-screens.js` | 6画面が本当に描かれるか。偽データは**本物の進行役から作る** |

`tests/realtime-auction.js` は締め切りを手前に引く `rush()` を使って
実時間待ちを避けている。**遊びの持ち時間を、検査を速く終わらせるために
歪めない**ため。そのかわり「締め切りが実時間で本当に効く」ことを見る検査を
1件だけ、早送りを使わずに置いてある。
