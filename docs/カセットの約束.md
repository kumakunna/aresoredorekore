# カセットの約束 v1（指示68-3）

新しいカセット（部屋で遊ぶゲーム）を足す時の約束。**新しい仕組みは作らない。** いまある部屋の芯（`realtime.js`）の
`GAME_DRIVERS` に1行足し、決まった形の進行役を1つ書けば、部屋・TV・文化祭の流れに乗る。
最初の1本は「みんなと同じ」（`onaji-room.js`）。迷ったら、それを手本に読む。

---

## 1. ファイルの置き場（1つのカセットで、だいたい5つ）

| 置き場 | 中身 | みんなと同じでは |
|---|---|---|
| `public/js/◯◯-logic.js` | 点・勝ち負けの決め方。画面も通信も知らない（UMD・node でも読める） | `onaji-logic.js` |
| `public/js/◯◯-bank.js` など | お題・問題などの中身だけ（運営が増減するもの） | `onaji-bank.js` |
| `◯◯-room.js`（リポジトリの直下） | 進行役。段階・締め切り・秘密・公開する物を決める | `onaji-room.js` |
| `public/js/v2-◯◯.js` | 画面の組み立て（新しい見た目・V2 の部品）。HTML の字を組むだけ | `v2-onaji.js` |
| `tests/◯◯-logic.js`・`tests/realtime-◯◯.js` | 決め方の検査と、本物のサーバーでの通し | 同じ名前 |

## 2. 進行役の形（`GAME_DRIVERS` の約束）

`realtime.js` の `GAME_DRIVERS` に `id: { driver: ◯◯Room, key: '◯◯' }` を1行足す。`key` は部屋に置く状態の名前（`room.◯◯`）。

進行役が持つもの（全部そろえる。足りないと `tests/big-screen.js`・`tests/room-paths.js` が赤くなる）：

| 名前 | 役目 |
|---|---|
| `PHASE` | 段階の表。**複数行で書く**（検査が `const PHASE = {` 〜 `\n};` を読む）。`LOBBY: 'lobby'` と `ENDED: 'ended'` を必ず持つ |
| `startGame(room, config, ctx)` | 人数の門（下限・上限）→ 状態を `room[key]` に作る → `room.state.game` を入れる → 最初の段階へ。`{ ok }` を返す |
| `publicView(room)` | 部屋の全員（TV を含む）に配る物。**白名簿で組み立てる**（状態を丸ごと写さない） |
| `privateFor(room, memberId)` | 本人だけに配る物（`wolf:you`）。関係ない人には `null` |
| `submitAction(room, id, targetId, payload)` | 押した時。端末が出す値を信じない（型・範囲を見る）。`{ ok, allDone }` |
| `submitVote` | 投票の形を使わないゲームは `submitAction` に渡すだけでよい |
| `isAllDone(room)` | 全員そろったら真（芯がすぐ `advance` する）。**つながっている人だけで数える**。だれもいなければ偽 |
| `advance(room)` | 締め切り・全員そろった・進行役の「すすめる」の全部がここに来る |
| `resultView(room)` | 決着の中身（記録と結果の画面が読む） |
| `clockKind(room)` | 時計の種類。`'play'`（卓のみんなが待つ）・`'turn'`（手番の人だけ）・`'tick'`（だれも待たない）。**既定は消さない**（空の部屋で `'tick'` を返さない） |
| `expectedMembers`・`undecidedIds` | まだ押していない人（待っている人の名前を出す所が読む） |

締め切りは `w.deadline` に置くだけ。芯が0.5秒ごとに見回って `advance` を呼ぶ（進行役が時計を持たない）。

### 段階の名前

段階の札は全ゲームで1枚の表（`index.html` の `RT_PHASE_LABEL`）。**ほかのゲームが使っている名前を使わない**
（例：`open` は False or True の「ケースが開く」なので、みんなと同じは `unveil`）。新しい段階は表に1行足す。

### 決着の記録

`realtime.js` の `recordMatch` に `if (room.◯◯) return record◯◯Match(room);` を足し、`saveMatchRecord` で残す。
順位を出さない遊び（協力）は、だれの点も付けない。

## 3. 秘密（いちばん大事）

- 秘密は `room[key]` の中にだけ置き、**公開（`publicView`）には段階を見てから入れる**。
- 本人の物は `privateFor` で本人にだけ。
- 検査は「届いた物を全部つないで探す」形で書く（`socket.onAny` で、TV とほかの端末に届いた物を全部ためて、秘密の字が無いことを見る）。
  手本：`tests/realtime-onaji.js` の門1。見張っている物が**届いていること**も同じ検査で見る（何も届かずに緑にならないように）。

## 4. 端末の側（`public/index.html`）

足す所（`tests/inventory.js`・`tests/room-paths.js` が漏れを見つける）：

1. `MODES`：遊び方ごとに1行。**属性の並びは `roomOnly → game → minPlayers`**。`tv` はルールの札3枚、`bullets` はルールの全文
2. `CASSETTES`：棚の1枚。門を通るまでは `hidden: true, testing: true`（くまくんの棚にだけ「テスト中」で出る）。`theme` は世界の名前
3. `GAMES`：ゲームの名前と上限（`◯◯-logic.js` の上限と一対）
4. `RT_START_CONFIG`：始める時に送る設定（送るのは決めごとだけ。中身の正本はサーバー）。検査用の最小設定を `tests/inventory.js` の `RT_START_MIN_CONFIG` にも1行
5. `RT_GAME_SCREENS`：そのゲームの画面。新しい見た目なら `scr-v2-◯◯`（スマホ）と `scr-v2-◯◯-tv`（TV）の2枚。`rtWantScreen` で振り分ける
6. 描く関数（`◯◯Render`）を `rtRenderCurrent` の振り分けに1行。押した時の動きは画面の箱に1つの `click`
7. 言葉は `public/js/ui-text.js` に（画面の組み立ては字を持たない）

### 画面（新しい見た目）

- 部品は作らない。V2 の部品（`v2-kit.js`）と、文化祭の部品（投票の札 `.v2-vlist`／`.v2-vcard`、TV の外枠 `V2Fes.tvc`）を使い回す。
- 世界（色と印）を1つ持つ：`v2-kit.js` の `WORLDS`、CSS の `.v2-w-◯◯`、`v2-art.js` の印。ほかのゲームの世界を借りない（大切なこと9）。
- 動きは「その段階を初めて描いた時だけ」（画面の箱の `.is-play`）。長さはどれも `--fx-scale` をかける（演出「なし」で止まる）。
- TV の字は 42px 以上（`tools/v2-shot.js` の check.js）。16人でも読める並びにする。

## 5. 文化祭の流れに乗せる

`fes-room.js` の `FES_GAMES` に1行：`{ mode, game, min, max, on: false, testing: true, start: { ... } }`。
文化祭の部屋の「遊ぶ」段階は、ふだんの部屋と同じ画面を通る（`fesWantScreen` が null を返し、`rtWantScreen` が振り分ける）。
結果の画面（つづける？）は文化祭の画面が受け持つので、`v2-fes.js` の `result`・`tvResult` から、そのゲームの結果の中身を呼ぶ。
門を通ったら `on: true` にする（くまくんの決め）。
