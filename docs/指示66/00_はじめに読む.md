## 見本の見方

- `見本/index.html` を Chrome で開く。インターネットにつながっていれば書体も出る
- 画面は本物の大きさ（スマホ 390×844、TV 1920×1080）で作って、縮めて見せている。「大きく」を押すと本物に近い大きさで見られる
- ページ上の切り替え：演出（普通・速い・なし）、スマホ（ふつう・小さい 375×667）、TVの安全な枠
- **画面の右の説明（箇条書き）が仕様。** 見た目は画面を、決まりは説明文を正とする
- 見本の作り（`見本/assets/ds.css`・`ds.js`）は、見た目を伝えるためのもの。アプリにそのまま貼らない（66-1「入れ方」）
- 撮る：`npx playwright install chromium`（初回だけ）→ `node tools/shot-mockup.js 見本 out/mockup`

## 見本どおりにしない所（見本より、こちらが優先）

2026-10-23 にくまくんが見本を見て決めたこと。見本に残っていても、こちらに合わせる。

1. **投票は外れない。** 投票した後に別のゲームを押しても、投票は変わらない（押し間違いで外れるのを防ぐ）。ルールのボタンと長押しは、今までどおり使える
2. **投票中は票の数を出さない。** どのゲームに何人入れたかを、スマホにもTVにも出さない（人に合わせて選ばないように）。決まった時だけ出してよい
3. **むずかしさは自分で選ぶ。** 大きい縦の並びで、最初はどれも選んでいない。自分で押すまで「入る」を押せない
4. **「いる人」の一覧（下から出るシート）で札を切らない。** 札が途中で切れないように高くする。多い時はスクロール。係が名前を消したら、スマホでもTVでもすぐ消える
5. **感想（★）は星を押した時点で送る。** カードが開いている間は、別の星を押せば直せる。押したら「送りました」と出す。「ひとこと書く」は別に送る
6. **ゲームをえらぶ間、TVは変えない。** 「進行役がいま見ているゲーム」はTVに出さない。選んでいる間、TVはQRと名前のまま（66-3）

ほかの細かい直し（中心・改行・重なり・のこり時間・縦の英字など）は、66-1 の「全部の画面の決まり」にある。

## 大切なこと・決めたこと（CLAUDE.md §2 と同じ。変更禁止・追加のみ可）

1. プレイヤーファースト：実装に時間がかかっても、プレイヤーが矛盾や混乱に遭遇してはならない
2. 1つずつ完璧に：次のゲームに進む前に、今のゲームを完璧に仕上げる
3. 収益化しない：広告・ガチャ・課金要素は一切入れない
4. 人を集める道具：スマートフォンを人を孤立させるのではなく、集める手段として使う
5. 心理的配慮は設計で：「連帯責任」的プレッシャーは排除し、協力と主体性の文脈で設計する
6. ルールの伝え方：情報密度を下げ、1スライド・1アイデアの原則
7. UI品質基準：iOS水準のレスポンシブ感（アニメーション0.2〜0.3秒）
8. デプロイ運用：自動デプロイを徹底し、手動作業の苦痛を排除する
9. 借りたものは世界観ごと運ばれる：外部素材・概念を借用する際は世界観ごと引き取る
10. 一つの点からすべてを喜ばせる：単一のメカニクスから全プレイヤーが主役になれる設計を目指す

## 運用の鉄則

- くまくんとフレンズはデバッガーではない。自分で検証を尽くす
- 完了報告は、本当に検証した時だけ。門の行に証拠がそろうまで「完成」「直った」と書かない。そろわない行は「未検証」と書く
- push は、その指示の「完成の門」が全行そろい、クリーンな1回の `npm test` が緑の時だけ（CLAUDE.md §5）
- バグ直しは、失敗するテストを先に書いてから直す
- ループのテストはマスターデータを見る。ハードコードしない
- 新しく見つけた落とし穴は CLAUDE.md に足す
