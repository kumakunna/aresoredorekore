## これは何

- くまくんから（11/4）：「勝手に巻き戻ることがある」「机を増やせるように」「右の長机（いす4つ）は短い机2つをくっつけた物なので、分けられるように」「いすの無い小さい机はケーブルが無いので、動かし放題に」「傘立てを動かせるように」
- Claude チャットがページを直して確かめた：`docs/指示72/haichi.html`
- 巻き戻りの原因（どれもページの中。サーバーは悪くない）
  1. 机を動かしている間に届いた保存先の答えを、動かし終わった時にそのまま入れていた → 直したばかりの所が消える（1人でも起きる。いちばん多い）
  2. 送る前に聞きに行った古い答えが、送り終わったあとに届くと、その古い形で上書きしていた
  3. 2人が同じ案を直すと、あとから送った方で案をまるごと上書きしていた
- ページの直し方：送り終わった版（`rev`）より古い答えは使わない／動かし終わったら聞き直す／送る前に保存先の今の形を聞き、「元・手元・保存先」の3つをくらべて、物（机・いす・エリア…）ごとに合わせる
- 見本サーバーで「今の版は赤・新しい版は緑」を確かめた（`docs/指示72/見本_巻き戻りの確かめ.js`）

## 2. 古いページで、新しい形の案が消えないようにする（サーバー）

- 新しいページは、全部の道に見出し `x-haichi-v: 2` を付けて送る
- `PUT`・`DELETE /api/haichi/plans/:id` で、この見出しが無い・2より小さい時は **409**（本文 `{"error":"old page"}`）。GET と `/haichi` はそのまま
- なぜ：push の前から開いたままの古いページは、分けた机・増やした机・カフェの札・傘立て・固定を知らない。古いページで保存すると、それが消える。409 なら古いページには「保存先につながりません」と出て、開き直すきっかけになる（見本サーバーで確かめた）
- `PUT`・`DELETE` の答えに `rev`（書いたあとの版の数）が入っていることを確かめる（指示70 の見本どおり）。入っていなければ足す。ページは `rev` で古い答えを見分ける（無くても動くが、そのぶん多く聞き直す）
- 今の配置づくりの検査で `PUT`・`DELETE` を送っている所には、この見出しを足す
