## 0. この指示で使えるようになるもの（1文）

### 見つけたこと

1. **iPhone（いちばん大事）**（写真1・写真2）
   - 投票で札はえらべる（枠と ✓ が付き、下が「〇〇に投票する」になる）。でも、そのボタンが押せない。結果の「つづける」も押せない

   - その前に、iPhone で別のアプリに切りかえていた
   - 読み込み直すと、名前を入れる画面になった（部屋から外されたあとの、今の形）
   - **Android（Samsung Internet）でも起きた**：別の画面に40秒切りかえてもどると、「つぎの回に入れます」の画面になった（18:10ごろ）。iPhone だけの話ではない
2. **ひとこと書く**（写真3・Android）：待合の「ひとこと書く」のシートで、書く箱がつぶれて下の線しか見えない
3. **Android の名前の箱**（写真4・写真4の拡大）：名前を入れる時、入力の中に白い箱と緑っぽい枠が出て、字の上下が切れる（字が大きいのではない。ブラウザは Samsung Internet）

### 1 の原因（Claude チャットがコードを読み、テスト用の1人で同じことを起こした）

- サーバーは10秒ごとに各メンバーの socket に `hb:ping` を送り、25秒 `hb:pong` が無いと `markDisconnected`（`connected=false`・`socketId=null`・`goneAt`）にする
- ところが、通信（WebSocket）そのものは切れていないことがある。iPhone は別のアプリに行くと Safari の JS が止まるが、通信は socket.io の ping の時間（45秒くらい）までは残る。もどってきても：
  - `hb:pong` の受け口は `lastSeen` を直すだけ。`connected`・`socketId` はもどさない
  - `socketId=null` なので、`hb:ping` がもう届かない（`socketOf` が null）→ 二度ともどらない
  - その socket は `room:（コード）` の流れには入ったまま。だから、みんなへの知らせ（ハート・解除の数）は届く。本人だけへの知らせ（`emitPrivate`：盤・`fes:you`）は届かない → 盤が空・投票した印が付かない・「つづける」を押しても何も変わらない
  - 次のゲームの始まりで「つながっていない人」として外れる。待合・呼び込みで `goneMs`（2分）たつと部屋から外される。スマホは部屋の画面のまま止まる
  - 投票・つづける の失敗（`not_player`・`not_in_room`）は、スマホに何も出ない（`rt.fesVote(...)` の答えを見ていない）
- 同じことを起こした手順（本番・テスト用の 🐻くまさん・11/6 18:01）
  - そのタブで `WebSocket.prototype.send` をかぶせて、`"hb:pong"` を含む送信だけを40秒捨てた（ほかは通す）。投票中に始めた
  - 40秒後に元にもどした。通信は生きたまま。その人は次のゲームで「ゲームの途中で入ったので、今回は TV を見ていてね」になり、もどらなかった。ほかの7人は普通に遊べた
- 当日：来た人が LINE やカメラに切りかえて、だいたい25秒〜45秒でもどると、iPhone でも Android でもこれになる。今は、ページを読み込み直すしか、もどり方が無い

### 2 の原因（PC の Chrome でも同じ形になった）

- `.v2 .v2-sbody{flex:1;min-height:0;overflow:auto}`。高さを決めていない（`is-tall` でない）シートでは、`flex:1`（`flex-basis:0%`）なので中身の箱が縮む
- 同じ形（タイトル・textarea・「送る」）を PC の Chrome（500×641）で開くと、シート 219px・`.v2-sbody` 11px・textarea 84px → textarea がほとんど見えない
- **Android だけの話ではない。** `is-tall` でないシートは全部同じ形：いる人・アイコンと二つ名（`is-mid` も）・ひとこと・端あわせ・ホームの QR・TV・メニュー など。全部見る
- 指示68-0b B1（部屋の QR のシートで、コードの箱が 11px まで押しつぶされた）と、たぶん同じ根っこ

### 3 は原因がまだわからない

- PC の Chrome で同じ箱を作ると、入力は高さ 50px・`line-height:normal`・枠なし・背景なしで、問題ない
- Samsung Internet では、入力そのものに白い背景と緑っぽい枠が出て、字は高さ 13px くらいの帯の中だけ見える（写真4の拡大）
- 疑う所：自動入力（`autocomplete="nickname"`）の時の色、`appearance:auto`、入力の行の高さ（`line-height:normal` と「M PLUS 1」）、`height:100%`

## 1. つなぎ直し（いちばん大事）

- めざす形：**通信が生きている socket から何か届いたら、その人を「つながっている」にもどし、`socketId` をその socket にして、いまの全部（みんなへの知らせ＋本人だけの知らせ）を送り直す。** これを1つの関数にする（道ごとに書かない・落とし穴17と同じ考え）
- `hb:ping` が `member.socketId` だけに頼らないようにする（`socketId=null` でも、その部屋に入っている生きた socket には届く）。または、スマホからも自分で知らせる。どちらにするかは CC が決めて、理由を報告に書く
- スマホ：画面がまた見えるようになった時（`visibilitychange` で visible・`pageshow`）、すぐに「いるよ」を送る（10秒待たない）
- **部屋から外されたあと（2分たった）にもどってきた時：止まった部屋の画面のままにしない。**（くまくんが 11/6 に決めた：案A）入る画面にもどし、名前とむずかしさは入ったまま、「しばらく はなれていたので、もう一度 入ってね」を出す。「入る」を1回押せば入れる（満員・予約・名前の決まりは、今の入口のとおり）
  - 通信が切れて socket.io がつなぎ直した時（45秒より長く離れた時）に、今どうなるかも確かめる。2つの道（通信が切れた／切れていない）で、もどった時の形を同じにする
- 押した時の失敗を、何も出ないままにしない：投票・つづける・準備OK・マスを開く・答える で `ok:false` が返ったら、短い一言（例：「つなぎ直しています」）を出して、つなぎ直す。文言は `ui-text.js`
- 変えないもの：つながっていない人が次のゲームで外れること（もどってきたら、今のゲームは「TV を見ていてね」、次の投票から入る）・2分で部屋から外すこと・30秒の席の取りおき・25秒の判定

## 2. シートの中身がつぶれない

- `.v2 .v2-sbody` を、中身の高さを元にする形にする（例：`flex:1 1 auto`）
- 保つこと：`is-tall` のシートは下まで伸びる／入りきらない時は、シートが 90% まで高くなり、それでも入らなければ中が巻ける／B1 の直し（`.v2-sbody > *{flex-shrink:0}`）
- キーボードが出た時（画面の高さが 400px くらいになった時）も、ひとことの箱と「送る」が見える

## 3. Android の名前の箱

- まず Playwright（Chromium・Android の形・Galaxy の大きさ）で同じ形が出るか見る
- 出なくても、どのブラウザでも同じになるように固める（例：`appearance:none`、行の高さをはっきり決める、自動入力の時の背景と字の色を固める、枠の色は外の `.v2-inp` に `:focus-within` で出す）
- 字の上下が切れないこと（56px の箱の中で、上下に余白がある）
- ひとことの textarea にも同じ考えを当てる

## 4. 確かめる

- 1：**先に赤**。サーバーの検査で「socket はつながったまま、`hb:ping` に25秒より長く答えない → そのあと答える／何か押す」を作る。直す前は「もどらない・本人だけの知らせが届かない・投票できない」、直したあとは「もどる・`fes:you` と盤が届く・投票できる」
- 1：2分より長く離れて外されたあとにもどった時：入る画面と一言が出て、「入る」で入れる
- 1：通信が切れてつなぎ直した時（45秒より長い）も、同じ形
- 1：これまでの「入り直し」「別の socket での入り直し」「TV」「スタッフ」「予約」の検査が緑のまま
- 1：本物の Chrome で、上の手順（`"hb:pong"` を40秒捨てる）→ もどってから次の投票で押せる（写真）
- 2：`is-tall` でないシート全部を、直す前と後で写真（360×740・390×844）。高さ 400 にした時のひとことのシート
- 3：Android の形の写真（直す前と後）
- `npm test` が1回で緑（版の検査はのぞく）
