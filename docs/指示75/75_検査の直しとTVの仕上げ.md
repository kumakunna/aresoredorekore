## 2. 束1：当日困る（11/12 までに必ず）

### 1-1 iPhone・iPad の Safari で上が切れる・下に余白（A05）
- 起きたこと：iPhone（iOS 26.5）と iPad（iOS 27.0.1）の Safari で、画面が切りかわったあと上が切れ、下に余白。スクロールしても直らない。クイズ解除ではライフ・時計・⚙ が見えなくなった。16:50 は iPhone で名前を打っても出なかった（**キーボードだけでは起きない・条件はまだ不明**）
- 手がかり：Android の全359場面で、ページの高さ（scrollHeight 854）が見えている高さ（innerHeight 758）より **96px 長い**（A13・`全画面_1158/scenes.log`）。Apple の開発者フォーラムに、iOS 26 の Safari でキーボードを閉じたあと visualViewport.offsetTop が 0 にもどらず、fixed の物がずれる・下に空白ができる、という報告が多い（https://developer.apple.com/forums/thread/800125 ・ https://developer.apple.com/forums/thread/799216 ）。ページが画面より長いと起きやすい、とも
- 直す形（CC がえらんで報告）：
  - (a) ページを画面より長くしない（96px の元を探して消す。100dvh・safe-area・帯の足し算など）
  - (b) visualViewport の resize・scroll と、画面の切りかわりの時に、位置と高さを合わせ直す（scrollTo(0,0) など）
  - (c) 条件を探す記録：画面が変わるたびに innerHeight・visualViewport.height・offsetTop・scrollY・scrollHeight を端末の中に最近50件残し、係が見られる形（送らない）
- 門：390×844・375×667・411×758 で全場面 scrollHeight ≤ innerHeight（道具で）。くまくんの iPhone と iPad で「名前を打つ→入る→画面を5回切りかえる」を3回、見切れ・余白なし（くまくんに頼む1行を報告に書く）

### 1-2 裏から戻った時・切れた時に、古い画面が押せそうなまま（A03・A07・A09）
- 起きたこと：Android（Samsung Internet）を40秒裏に回して戻すと、古い画面（0秒の問題など）が押せそうな見た目のまま 1.3〜5.5秒（3回中1回だけ3秒以内）。合図なし。機内モードでも数字が動き続け、「つながっていません」が出ない。3分裏 → 入る画面まで 4.8〜5.6秒
- 直す形：つながっていない間（通信が切れた・裏から戻って最新をもらう前）は、画面の上に「つなぎ直しています」を出し、押すボタンを押せなくする。最新が届いたら消す（0.2〜0.3秒）。オフライン（navigator.onLine）も同じ
- 門：検査で「切れた→合図が出る→押しても送らない→もどったら消える」。くまくんに頼む：Android で40秒→戻る（合図が出て、古い画面を押せない）

### 1-3 回線の切りかえ（4G⇔5G）で切れて、次のゲームに入れない（A04）
- 起きたこと：Android が何もしていないのに、次のゲームで「途中で入ったので、今回は TV を見ていてね」。Console に ERR_NETWORK_CHANGED ×3
- 直す形：席の取っておき（holdMs 30秒）の間にもどった人は、次のゲームに入れる。どこで「途中から来た人」になったかを先に調べて報告（サーバーの記録が無ければ手元で通信を10秒切って同じことを起こす）
- 門：検査「10秒切れる→もどる→次の回に入る」

### 1-4 読み込み直すと、同じ人が2人（A15）
- 起きたこと：Android で「入る」のあと同じタブで読み込み直すと、同じ名前が2人。**約2分で1人にもどった＝帰った人を外す時間（fes-room.js goneMs 120000）と同じ**。Claude の2回（待合で読み込み直す／入るの0.3秒後）では起きなかった。13:50 ごろ回線が不安定（A16 の近く）
- 見込み：読み込み直しの時に前の席を名乗れず新しい人になり、前の席が goneMs の間残る。どの時に名乗れないか（席の札を保存する前に読み込んだ・名乗りが届く前に切れた など）を調べて報告
- 直す形：同じ端末なら、読み込み直しても前の席にもどる（または前の席をすぐ外す）
- 門：検査「入る→0〜1000ms のどこかで読み込み直す」を20回、いつも1人

### 1-5 TV の時計がずれると数えがずれる（A12）
- 起きたこと：PC の時計が1.9秒進んでいて、TV の数えが約2秒早く0になった。`V2.setClockOffset` は作ってあるが、どこからも呼ばれていない（v2-kit.js）
- 直す形：入った時とつなぎ直した時に、サーバーの時計とのずれを測って setClockOffset する（そろえて発射の clock:sync と同じ考え）
- 門：検査で PC の時計を ±2秒ずらしても、数えの0がスマホと 0.3秒以内

### 1-6 係が外した人を、しばらく入れなくする（くまくんの決め）
- 形（くまくんの答え 7.A）：係の画面の「外す」を**ふつうに押す＝今のまま**（すぐ入れる・字は「部屋から出ました。もう一度入れます」）。**「外す」を長押しすると「30秒」「1分」「5分」の選択肢**が出て、えらんだ時間はその人が入れない。その人のスマホの字は「しばらくしてから入れます」（責めない言い方・のこり時間を出すかは CC の案で）
- 気をつけること：長押しは気づかれにくい → ボタンの下に小さく「長押しで、しばらく入れない」。スマホの長押しで字のえらび・メニューが出ないように（user-select・-webkit-touch-callout）。長押しの長さは 0.5秒くらい・ふつうの押しとまちがえない
- 「入れない」は同じ端末と同じ名前の両方で（名前だけ変えて入り直せない形を、どこまでやるかは案を報告）
- 門：検査（長押しで3つ出る・30秒の間は入れない・すぎたら入れる・ふつうの押しは今のまま）

## 4. 束3：TV の切りかえの直し（11/12 までに）

本物の TV 2台の代わりに、11/7 にプロジェクター2台＋ノート PC で通した（`記録_1107.md` A22〜A32・`tvs/`）。合格した所は変えない（押してから 0.03〜0.05秒・開き直し・サーバーの入れ直し・ゲーム中は自動で切りかえない）。

- 3-1（A28）**だれも呼ばれていないのに「あそびまちの呼び出し」**：「はじめる」・あそびまちのタブの読み込み直しのたびに（5回中4回）。あそびまちのページが開いた時の音（「押すと始まります」を押した時など）を、タブの「鳴っている」で呼び出しと数えている。直す形（CC がえらぶ）：読み込みから20秒は数えない／モニターの「お呼び出し」の欄の字が変わった時だけ数える（読むだけ・あそびまちのコードにはさわらない）
- 3-2（A25・A27）**全画面が外れたら自分で戻す**（Esc・F11・画面のつなぎ直しで外れた時、2秒以内に）。「はじめる」の押し直しで、窓を一瞬ふつうの大きさにしない（その窓にあそびまちが出ていると、アドレス欄に key が一瞬出る）
- 3-3（A26）**あそびまちが開けない時、拡張機能が自分で開き直す**（エラーの画面のままにしない。30秒ごと・見えた時）。今は Chrome が自分で読み直すのを待つだけ（見えているタブで16秒で戻った・裏のタブは未確認）
- 3-4（A29）「はじめる」の画面が TV の上にあってもまちがえない（主の画面＝ノート PC をのぞく・または はじめる の画面を先にノート PC へ動かす）。画面の数や並びが変わったら（chrome.system.display.onDisplayChanged）、TV の窓を置き直す
- 3-5（A32・くまくんの決め）**TV ごとに音を出すスピーカーをえらべる**。今は Windows の出し先1つ（SteelSeries Sonar）から全部出るので、TV を入れかえても音の場所は変わらない。AudioContext.setSinkId（Chrome 110 から）・HTMLMediaElement.setSinkId で、TV① の物は TV① の HDMI へ。あそびまちのチャイムも TV② の窓の物は TV② へ出せるか。**先にできるかを調べて報告**（出し先の一覧は、マイクの許可で増える＝TV 専用の Chrome で1回だけ許可する形になりそう）。間に合わない時は、当日は Windows の出し先を TV① に合わせてしのぐ（運用メモに書く）
- 3-6（A24(b)）あつまれを出している TV② を、人がいる間（呼び込み以外）は呼び出しでも動かさない（回すのと同じ決まりに）
- 3-7 リモコンに「左」「右」も出す（例「TV①（左）」）。どちらが左かは「はじめる」の画面で決まる（入れかえたら名前も入れかわる）
- 3-8（A22・A30）**TV 専用の Chrome でない所で「はじめる」を押させない**：11/7、拡張機能がふだんの Chrome に入り、「はじめる」も押され、TV の PC が2台になりかけた。見分け方の案：音が人の操作なしで鳴らせるか（--autoplay-policy の有無）を「はじめる」の画面で確かめ、ちがえば大きく「TV 専用の Chrome で開いてください（デスクトップの『あつまれ TV』）」

## 5. 束4：TV の動画と、リモコン・準備の使いやすさ（くまくんの決め・11/12 まで・束3 のあと）

- 4-1 **動画と画像を2つずつ、別々のボタンで**：動画1・動画2・画像1（メニュー）・画像2。リモコンのボタンは、設定した物の数だけ増えたり減ったりする（スクロールせずに全部押せる形を、物の数に合わせて変える）
- 4-2 **印（マーカー）**：TV の PC の「はじめる」の画面（動画をえらぶ所）に、動画の小さな見本（再生・止める・前後へ・いまの時刻）と「ここに印」（名前を付ける）。印の一覧で名前を直す・消す・並べかえ。印は動画といっしょに TV の PC に覚え、名前と時刻だけをサーバーに教える（リモコンに出すため）
- 4-3 **係のスマホで、印の一覧から押して飛ぶ**：その TV に動画が出ている時、リモコンに印の一覧・再生／止める・10秒もどす／すすめる・いまの時刻
- 4-4 **範囲とくり返し**：始めと終わり（印からえらぶ・時刻でも）を決めると、そこだけ流す。くり返しの入／切。「自動で回す」の「1回分」は範囲の長さ
- 4-5 **再生する位置**：「ここから流す」（はじめの位置）
- 4-6 **使いやすさ**（くまくん「正直まだ使いにくい」）：リモコンと「はじめる」の画面の、使いにくい所と直す案を先に一覧で報告 → くまくんがえらんだ物を入れる（例：はじめる の画面を「1 はじめる 2 TV に出たか見る 3 音の出し先」の順の手順にする）
- 門：tests/tvs.js に足す。tvs-walk で、印へ飛ぶ（押してから TV が動くまで 1秒以内）・範囲のくり返し（終わりで始めにもどる・前後 0.3秒以内）・ボタンの数が増えても 390×844 でスクロール無し

## 5b. 直さないこと（くまくんの決め）と、CC に聞くこと
- A14 TV がスマホより約0.27秒おくれて見える：学校の TV はもうゲームモード。配線と HDMI の分配器（スプリッター）のための遅れで、しかたない（くまくん）。アプリの記録でも、TV の方が早く受け取っている。**直さない**

## 6. くまくんに確かめてもらうこと（push のあと・報告に1行で）
