# 6：スマホと TV の遅れを、学校の回線で測る手順（11/7 用・CC が作った）

## 何を測るか
サーバーが知らせを出すたびに、その直前に「いま出す」とサーバーの時刻を送る（`lag:t`）。端末は次に来た同じ名前の知らせと組にして、次の3つを測る。
- **net**：サーバーが出した → 端末が受け取った（時計は `clock:sync` で合わせる。合わせ方の誤差は往復の半分＝記録の `rtt`/2 まで）
- **受け口**：受け取った → 画面を組み立て終えた
- **paint**：受け取った → 画面に出た（次のコマが描かれたあと）

知らせの種類：部屋の知らせ（`room:update`）・本人だけの知らせ（`fes:you`・`wolf:you`）・3-2-1（`room:countdown`）・係の画面（`fes:staff`）。
役（スマホ／TV／係）・ゲーム・段（投票・準備OK・遊ぶ・結果…）ごとにまとまる。名前は入らない。

## 入れ方（本番）— **くまくんの OK が要る**
本番では `.env` に `PROBE` が無い限り何も動かない（道は 404・端末は何も送らない）。測るには：
1. 7・6 のコミットを push する（**今朝の push には入れない約束**。入れると言われた時だけ）
2. だれも遊んでいない時に、本番の `.env` に1行 `PROBE=err,lag` を足して `pm2 restart`（再起動で部屋は消える＝係が作り直す）
3. 測り終わったら、その行を消して `pm2 restart`（消すまでは、全部の端末のエラーと遅れを受け取り続ける）
- 置き場：本番の `data/probe/errors-日付.jsonl`・`lag-日付.jsonl`（1日 20MB まで・1つの IP から1分に600回まで）

## 測る順番（1つの条件を 15〜20分。始めと終わりの時刻をメモする）
| # | 回線 | すること |
|---|---|---|
| A | 学校の Wi-Fi | スマホ（iPhone・Android・iPad）と TV で、ふつうに2〜3回遊ぶ（投票→準備OK→遊ぶ→結果） |
| B | スマホの回線（Wi-Fi を切る） | 同じ |
| C | 学校の Wi-Fi・**電子レンジを動かしている間** | 同じ（レンジの近くの端末と遠くの端末を1台ずつ） |
| D | 学校の LAN の PC（係の画面・TV の PC） | 係の画面を開いたまま（`fes:staff` が入る） |
- どのゲームでも測れる。そろえて発射・ぴったり10秒は、見せ場の時刻合わせに遅れが効くので、1回ずつは入れる

## 読み方（本番のサーバーの中で・読むだけ）
```
node tools/probe-report.js --lag --since 13:00 --until 13:20
node tools/probe-report.js --errors
```
条件ごとに `--since`・`--until` を変えて読む。表の見方：
- net の中央と 95%：回線そのもの（A と B と C をくらべる）。95% が 1秒を超える段は、見せ場がずれる
- paint の 95%・最大：端末の重さ（古いスマホ・TV の PC）。受け口が大きければ画面の組み立てが重い
- `rtt`（往復）が大きい端末は、net の誤差も大きい（rtt/2 まで）

## 手元の数字（11/7 未明・くらべる元）
手元の PC（Chrome 4台：スマホ3＋TV・同じ PC の中の通信）で全ゲームを回した結果は `docs/検査_1107/6_手元の遅れ.md`。
回線の遅れはほぼ 0 なので、学校の数字との差が「回線のぶん」になる。

## 動画で測る（記録とは別に・目で見える遅れ）
- iPhone のスロー（240fps）で、**TV とスマホを1つの画面に入れて**撮る。同じ場面（3-2-1 の「1」・決定の幕・そろえて発射の点火）を10回以上撮り、コマを数えて **まん中の値**
- TV そのものの表示の遅れも別に測る（TV の「ゲームモード」入／切で同じ場面を撮りくらべる）
- **scrcpy の画面では測らない**（scrcpy にも遅れがある）
- 合格の線（仮・くまくんの「追加」）：TV とスマホの表示のずれ まん中 100ms 以内・いちばん悪くて 200ms 以内

## 時計の合わせ方（記録の net の正しさ）
- 8回たずねて、**往復がいちばん短かった回**の差を使う。つなぎ直した時・画面がまた見えた時・1分ごとに測り直す
- 画面に出た時刻は `requestAnimationFrame` の中で取る（そのコマを描く直前）

## そろえて発射・ぴったり10秒の判定は、表示の遅れに左右されるか（コードを読んだ答え）
- **そろえて発射**：押した時刻を、スマホが `clock:sync` のずれで **サーバーの時刻に直して** 送る（index.html `soroeFire` → `at`）。
  サーバーはその時刻どうしをくらべる（soroe-room.js `submitAction`）。→ 表示の遅れでは変わらない。変わるのは時計合わせの誤差（往復の半分まで）
- **ぴったり10秒**：スマホが **自分の時計（performance.now）で、自分の画面の「スタート」から押すまで** を測って ms を送る（index.html `pittariStop`）。
  サーバーはその ms をそのまま使う（pittari-room.js）。→ 回線の遅れも時計のずれも入らない。スタートの合図がスマホに遅れて出ても、その人の10秒はその人の画面から数える
