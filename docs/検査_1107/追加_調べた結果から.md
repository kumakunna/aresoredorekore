## 1（チェック表）に足す行

- もどるテスト：40秒・3分に加えて、**画面ロック（電源ボタン）・5分以上・機内モード→もどす・Safari の別のタブに行ってもどる**。それぞれ3回
- 低電力モードの時・画面が暗くなる前（Wake Lock が効いているか。もどった時に取りなおしているか）
- 同じ人が QR を何度も読む・「戻る」ボタン・読み込み直し・2台で入る、の時の席
- TV の PC の Chrome：全画面で何時間も動かしても重くならないか
- **iPad を PC と思う所が無いか**：コードの中で UA（`navigator.userAgent`）でスマホ／PC を分けている所を全部さがして一覧にする（iPad の Safari は Mac と同じ UA。見分けるなら `maxTouchPoints > 1`。画面の幅と `(pointer: coarse)` で分けるのが本筋）
- 当日の朝に見る物：DuckDNS の HTTPS の証明書の期限・学校 Wi-Fi のログイン画面（キャプティブポータル）や WebSocket がふさがれていないか

## 3（耐久）に足すこと

- 見る数：CPU・メモリ（RSS）・**イベントループの遅れ**（`perf_hooks.monitorEventLoopDelay` の p99）・同時接続数・つなぎ直しの回数・emit→ack の p95・SQLite に書く時間
- 本番の数分の手順に、**止める条件**を先に書く（例：あそびまちの返事が遅くなった・CPU が70%をこえ続けた・エラーが出た → すぐ止める）。あそびまちの返事も同時に見る
- §6 の16 と一緒に、nginx の `proxy_read_timeout` が45秒より長いかを読む（読むだけ）

## 6（遅れ）に足すこと

- 時計合わせ：5〜10回たずねて、**往復がいちばん短かった回**の差を使う。もどった時（visibilitychange）と1分ごとに測りなおす
- 画面に出た時刻は `requestAnimationFrame` の中で取る
- 結果は、まん中の値（p50）と95%（p95）で出す。学校の Wi-Fi・スマホの回線・電子レンジを動かした時で分ける
- 動画で測る手順：240fps（iPhone のスロー）で、TV とスマホを1つの画面に入れ、10回以上測ってまん中の値。TV そのものの表示の遅れ（ゲームモード入／切）も別に測る。**scrcpy の画面では測らない**（scrcpy にも遅れがある）
- 「そろえて発射」「ぴったり10秒」が、スマホの表示の時刻ではなく、サーバーの時刻に直して判定しているかを確かめて書く
