# 演出の共通部品（第32弾-C）

## なぜ1か所に集めたか

「カードをめくる」「正解のフラッシュ」「点数のカウントアップ」「順位を1位から出す」は、
どのカセットにも出てきます。ゲームごとに書くと、**片方だけ直して、もう片方に
反映し忘れる**事故が必ず起きます。このプロジェクトで何度も踏んだ形です。

だから演出は `public/js/fx.js` に全部集め、各ゲームからは呼ぶだけにしてあります。

## 使えるもの

| 呼び方 | 何をするか | どこで使う |
|---|---|---|
| `FxKit.hold(ms)` | 演出の待ち時間。**タップで飛ぶ** | 演出で待つところ全部 |
| `FxKit.flash(kind)` | 画面全体のフラッシュ | 正解・不正解・大当たり・大ハズレ |
| `FxKit.banner({...})` | 画面いっぱいの演出 | 褒める瞬間だけ |
| `FxKit.flip(node, onHalf)` | カードを裏から表へめくる | お題・役職・品物 |
| `FxKit.countUp(node, a, b)` | 点数が増えていく | 加点・結果 |
| `FxKit.stagger(nodes, gap)` | 頭から1つずつ出す | 順位発表・コードの点灯 |
| `FxKit.fly(from, to, label)` | 印が飛んでいく | 票の集計 |
| `FxKit.alive(node, on)` | ごく控えめな脈 | 誰かを待っている時間 |
| `FxKit.notice(text, kind)` | 控えめな通知 | 切断・復帰 |
| `FxKit.shake(strength)` | 画面が一瞬（0.2秒以内・1回）揺れる | 爆発（スマホはここだけ）・処刑・大損失（大画面） |
| `FxKit.confetti(colors)` | 紙吹雪＋歓声 | **ゲーム全体の優勝だけ**（1ラウンド勝利では使わない） |
| ~~`FxKit.callout(text, opt)`~~ | **指示60 で仕組みごと削除**（大画面の英単語 TIEBREAKER 等）。13か所の置き換え先は `docs/監査_指示60の門.md` 1節 | 戻さない（`tests/fx.js` が0件を見張る） |
| `FxKit.vibe(name)` | 名前で呼ぶ振動パターン | rise / win / miss / sold / count3〜count1 |
| `FxKit.burst(icon, ms)`（第59弾） | 大きな絵文字が、大きさだけで伝える（拡大縮小のみ・点滅しない） | 爆発の💥。`cfg.can.flash` を通らない＝光の点滅を切っている人にも出る |
| `FxKit.shutter({...})`（第59弾） | 上から一気に落ちて、少し跳ねて止まる帯 | 爆発の結果（「爆発しました」）・すごろくの突然のできごと（大画面）・クイズの全問正解（大画面）。中身は `banner()` と同じ、出方だけ違う。`linger` を渡すと速さの設定で縮まない |
| `FxKit.blackout()`（指示60） | **黒い幕**。出た瞬間から不透明で、後ろのボタンを押させない。戻り値は「上げる」関数（指が離れてから上がる） | 爆発の💥と同じ瞬間（後ろで描かれる結果を透けさせない）。光を弱くする設定でも出る |
| `FxKit.linger(ms)`（指示60） | **速さの設定で縮まない、タップでは必ず終わる**待ち | 「爆発しました」の「2秒待つか押す」（スキップ設定でも有効） |
| `FxKit.celebrate({...})`（指示60） | **クリア演出**。主役の出方（flip／evolve／stamp／drop／rise／pop）と舞うもの（spark／card／coin／washi／tape）を世界ごとに選ぶ。地は出た瞬間から不透明。`behind` で「祝いの後ろで結果へ」 | 各カセットのクリア。世界の絵・色は `index.html` の `CLEAR_LOOK`（表）、部屋は `rtClearFx` 1か所。スキップ設定では描かない。光の輪だけは光を弱くする設定で出さない（大きさ・動きは出す） |

### 第32弾-D：安全に関する設定との関係

- `shake()` は `init` の `can.shake()` が false なら**何もしない**（「画面の揺れをつかう」OFF）
- 光の点滅系（`.fx-flash` `.bomb-boom` など）は、`#app` の `no-flash` クラスでCSSごと止まる
- **`.fx-burst`（第59弾）はこの門を通らない。** 光ではなく大きさの変化だけなので、
  安全基準§6の対象外——光の点滅を切っている人にも同じように出る
- **`.fx-blackout`（指示60）もこの門を通らない。**光の変化ではなく隠すための幕で、
  止めるとその設定の人にだけ結果が透ける
- **`.fx-cel`（指示60）は、光の輪（`.fx-cel-glow`）だけ止まる。**主役と舞うもの（大きさ・動き）は出す

### 指示60：舞台の「前座」

`flash`・`boom`・`dawn`・`burst`・`confetti`・`edge`・`blackout` は舞台（`stage`）を通らない。
その最中は舞台が空いて見えるので、**称号（褒める）が1拍で割り込んでいた**（実機報告）。
いまは、これらを**前座**として数え、**褒めるのは前座も済んでから**。
結果（帯・シャッター・クリア演出）は前座を待たない——「💥のあとに『爆発しました』」の順はそのまま。
**新しい画面いっぱいの演出を足したら、舞台に乗せるか前座に乗せるか、どちらかにする**
（どちらにも乗せないと、その隙間に称号がまた入り込む）
- BGM（`index.html` の `bgmSync`）は500msごとの見回りが「鳴らしてよい場面」を1か所で判定する。
  音声認識・読み上げを使う場面は判定に書かれていない＝絶対に鳴らない

## 守っている決めごと

### 原則B：スキップできない演出を1つも作らない

待ち時間は必ず `hold()` を通ります。`hold()` は**画面のどこかを触れば即座に終わり**、
しかも**連なった演出は一度のタップで全部飛びます**（1つずつ叩かせない）。

「演出の速さ」設定（32-B）は `ms()` 1か所で効きます。
新しい演出を書く時、速さの設定のことを考える必要はありません。

CSSの時間にも `var(--fx-scale)` を掛けます。

```css
animation:fxFlashGood calc(0.42s * var(--fx-scale)) ease-out;
```

### 原則C：褒める時は全力で、責める時は静かに

- 褒める → `banner()`。画面いっぱい・大きな音・鮮やかな色
- 責める → `flash('bad')`。**0.15秒・薄い赤・短い音だけ**

`banner()` に `'bad'` はありません。**作っていません。**
みんなで遊ぶ場で恥をかかせる実装ができないように、部品の側で塞いであります。
テスト（`tests/fx.js`）が、これを塞いだままかを見張っています。

### 原則D：待っている時間

`alive()` は、カセットのテーマごとに見た目が変わります。

| カセット | 待っている時の見え方 |
|---|---|
| 人狼 | 月明かりが微かに揺れる |
| 爆弾解除 | 制御盤のランプが点滅する |
| クイズ王 | 早押しボタンがゆっくり息をする |
| オークション | 燭台の灯がゆらぐ |

呼ぶ側は `FxKit.alive(node)` だけ。見た目はCSSのテーマ側が決めます。

### 原則E：切断・復帰

`notice()` は**音も振動も鳴らしません**。慌てさせないためです。
返り値も返しません（呼んだ側が待ちようがない＝進行を止めようがない）。

判定は、部屋の公開情報に前から載っていた1人ずつの `connected` の**差**を見ています。
サーバーには何も足していません。

## 結果のあとの「つぎは？」（第7部）

1試合終わるたびに、棚まで戻ってカセット→ゲーム→モードを選び直していました。
盛り上がった直後に何段階も選ばせると、せっかくの熱が冷めます。

出口は**6か所に散らばっていました**。

| どこ | 何があったか |
|---|---|
| `scr-score` | もう一度／モードをえらびなおす／記録して、つぎのゲームへ |
| 部屋の画面5つ | 「べつのゲームをえらぶ」が**5つの複製** |

これを `NEXT_CHOICES` という**1つの表**にまとめ、`scr-next` 1画面から出るようにしました。
選択肢の並びも文言も、この表だけが持っています。

```
🔁 もう一度（さっきと同じ設定でそのまま）  ← いちばん大きく、いちばん上
🎛 モードを変える
🎮 別のゲームへ
📚 別のカセットへ
```

### 決めごと

- **「もう一度」は最短。** 設定ウィザードも準備OK画面の長押しも通らず、
  そのままカウントダウンに入ります
- **押しても何も起きない選択肢は出しません。** ゲームが1つしかないカセットでは
  「別のゲームへ」を、モードが1つしかないゲームでは「モードを変える」を出しません
- **余韻を残します。** 結果発表から切り替わるとき、金色の光が1.1秒かけて内側から引きます
- **サバイバルは決着まで抜け道を出しません**（第20弾の決まりをそのまま守っています）
- **部屋では進行役だけが選べます。** 他の人には同じ場所に
  「進行役が つぎを選んでいます…」と出し、`alive()` でゆっくり脈打たせます。
  押せないボタンを黙って置くと、固まっているのか待たされているのか分かりません

テストは「どのボタンか」ではなく「どこへ行きたいか」で書きます。

```js
await chooseNext(win, doc, 'shelf');   // 別のカセットへ（ここで記録が残る）
```

## 新しい演出を足す時

1. `fx.js` に足す（各ゲームの中に書かない）
2. 待つところは `hold()` を通す
3. CSSの時間には `var(--fx-scale)` を掛ける
4. 褒める演出か、責める演出かをはっきりさせる

## 直したもの（第32弾-C）

**音量つまみが1つも効いていませんでした。**

`sfxOut()`（音の出口）が `g.connect(sfxOut(ctx))` と書かれていて、
自分自身を呼び続けていました。例外で `catch` に落ちるので音は鳴りますが、
つまみが数珠つなぎになって掛け算で効き、**100未満にすると実質無音**でした。

原因は32-Bで書いたテストです。
「`ctx.destination` につなぐ場所は0か所」という条件にしたので、
出口そのものがスピーカーにつなげなくなり、その矛盾を通すために
自分を呼ぶ形になっていました。**テストがバグを作った**形です。

条件を「出口の中で1回だけ、外では0回」に直し、
1回の音でつまみを作りすぎていないことも見るようにしました。
