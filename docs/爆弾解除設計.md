# 爆弾解除カセット 設計

このドキュメントは、カセット「爆弾解除」の設計と実装状況をまとめたものです。

関連ドキュメント：
- `あつまれあれこれ_棚全体の構想.md` … アプリ全体の構造・棚の段・全ゲーム共通で守ること
- `あれそれどれこれ_プロジェクト概要.md` … 技術構成・デプロイ・開発方針

---

## 全体構造

```
カセット：爆弾解除
  ├─ ゲーム：クイズ解除 ★実装済み
  │     └─ モード：クイズ解除（協力版）／クイズ解除（競争版）
  ├─ ゲーム：実物解除   … 削除（2026-10-24・指示68-1）
  └─ ゲーム：同時解除   … 未実装
```

人狼カセットと同じ3階層（カセット→ゲーム→モード）です。ゲームが2つになったので、
棚からカセットを選ぶとゲーム選択画面を通ります。

**実装順序**：クイズ解除を完成・検証してから実物解除に着手しました。
一度に手を広げると「片方だけ直して古いまま残る」事故が起きるためです（原則2）。
同時解除も、実物解除が実機で確かめられてから着手します。

棚の段は、いま遊べる中身（クイズ解除＝ことば・クイズ）に合わせて **ことばであそぶ** に置いています。
実物解除（傾け・振る・ポーズ）が入った時点で **からだをうごかす** へ移すことになります。

## ゲーム：クイズ解除（実装済み）

AIが作った説明文を聞いて3択で答え、コード（お題）を1本ずつ切っていきます。
旧「時限爆弾」を改名・拡張したものです。

### 協力版（モードid: `bomb-coop`）

> 第28弾-1で「通常版」から改名しました。idも `bomb` → `bomb-coop` に変えています。
> 記録は `rounds[].mode` にモードIDをそのまま持っているので、
> `LEGACY_MODE_IDS`（index.html）に対応表を1行置いて、
> 古いIDで残っている記録が迷子にならないようにしてあります。
> **今後モード名を変える時も、必ずここに1行足してください。**

協力プレイです。**1台のスマホと全員スマホのどちらでも遊べますが、その選択は入り口で済んでいます。**

| 入り口 | 遊び方 |
|---|---|
| 棚からカセットを直接タップ | **1台のスマホ**（手渡し）。第27弾より前と一切同じ挙動 |
| 棚の「部屋」から部屋を立てて選ぶ | **全員スマホ**（1人1台） |

第26弾-3で「何台で遊ぶ？」という選択そのものを無くしたので、モードカードは1枚で足ります。

**全員スマホの決まりごと**

- 全員が**同じ盤面（コード一覧）**を自分のスマホで見る。並び順も全員同じ
- ライフ・残り時間・解けた本数は**全員で共有**する
- **同じコードに2人が同時には挑めない**（先に開けた人が持つ）。他の人の画面には
  「びびが挑戦中」と名前が出る。2人とも外して1回のミスでライフが2つ減るのを防ぐため
- 正誤判定・ライフの管理はすべてサーバーが持つ
- 協力プレイなので、**個人の成績・順位はつけない**
- **「だれが外したか」は既定では出さない**（第45弾 45-4）。
  進行役が「このゲームの設定 →👀 だれが外したかを出す」をONにした試合だけ、
  外れた時に「◯◯さんが ◯ばんめのコードを外しました」と静かに出る。
  出るのは名前と番号だけで、**選んだ答えは配らない**——
  協力版は盤面を共有しているので、「あの人はこれを選んで外した」が残ると
  次に挑む人の3択が2択になる。外した本人には出さない（「💔 ちがう！」がもう出ている）

### 競争版（モードid: `bomb-race`）

**1人1台・部屋が必須**です。手渡し方式では選べないようにしてあり、
モードカードに理由（部屋を立ててください）が出ます。

- 全員が**同じコード一覧**に同時に挑戦する。観戦者は発生しない
- **コードの並び順は各自別々にシャッフル**する（隣の画面を見ても場所が一致しない）
- 各自の進捗（あと何問か）を、他の参加者にリアルタイム表示する
- **AIの説明文は、部屋の待機中に全部事前生成する。** サーバー側だけが持ち、
  試合が始まるまで1文字も配らない
- ミスペナルティ：**ライフ−1 と 残り時間−10秒 の両方を同時適用**
- ライフが0になると失敗＝**記録なし・最下位扱い**（順位を付けない）
- 終わり方を設定で選べる：**最初に全部解いた人が出た時点で終了**（既定）／**全員が終わるまで続ける**
- 順位：解けた問題数が多い順、同数ならタイムが早い順

### 大画面表示

- 各プレイヤーの進捗（解けた数）とライフを**横棒グラフ**でリーダーボード表示する
- **問題の中身・正解／不正解の詳細は一切表示しない**

### 心拍演出

爆弾解除カセット共通の演出として、背景に心拍音を薄く流し、**ミスするほど速くなる**ようにしています。
協力版（1台のスマホ／全員スマホ）と競争版のどちらにも入っています。

- 盤面に入ってから鳴りはじめる（説明文をそろえている間は静かなまま）
- 画面を離れたら必ず止まる（別のゲームを遊んでいる間に鳴り続けないこと）
- 常時BGMは入れない方針なので、音量は低く、声の帯域から離れた低音だけを鳴らす
- AudioContext は使い回す。`beep()` のように1回ごとに作ると、0.5秒間隔ではブラウザの上限を超えて音が止まる

## ファイル構成（クイズ解除）

人狼・ワードウルフと同じ「ルール層と進行層を分ける」形を踏襲しています。

| ファイル | 役割 |
|---|---|
| `public/js/bomb-logic.js` | ルール層。DOM非依存・Node.jsからも require 可。コードの抽選／3択の作り方／ミスの罰／順位／心拍の速さ |
| `bomb-room.js` | 進行層。1人1台の進行役。段階（prep→play→ended）・秘密の配り分け |
| `realtime.js` | `GAME_DRIVERS` に `bomb` を1行足しただけ。socketのハンドラは新しく書いていない |
| `ai-describe.js` | Geminiのプロンプトと呼び出し。`/api/ai-describe` とサーバー側の事前生成が共用する |
| `public/index.html` | 画面。手渡し（`scr-bomb-play`）／1人1台（`scr-rt-bomb`）／大画面（`scr-rt-big`） |
| `tests/bomb-logic.js` | ルール層の単体テスト（jsdom不要） |
| `tests/realtime-bomb.js` | 本物のサーバー＋複数接続での通し確認・秘密が漏れないことの確認 |

### 通信の形

`publicView` / `privateFor` / `submitAction` / `submitVote` / `isAllDone` / `advance` /
`expectedMembers` を揃えたので、socketのハンドラは人狼・ワードウルフと同じものが使われます。
イベント名は `wolf:` のままですが、届く先は「その部屋でいま遊んでいるゲーム」です。

爆弾解除での意味づけ：

| イベント | 意味 |
|---|---|
| `wolf:act` に uid | そのコードを開ける（説明文と3択が本人にだけ届く） |
| `wolf:act` に null | 開けているコードを閉じる |
| `wolf:vote` に答えの文字列 | **いま開けているコード**への答え。どのコードへの答えかを端末に決めさせないので、開き直しの競合で別のコードの正解が通ることがない |
| `advance` | 期限が来た人を締める。本当に期限が来たかを自分で確かめるので、余計に呼ばれても何も起きない |

### 秘密の扱い

- 公開情報（`publicView`）には、お題の名前も説明文も**一度も**入れない。
  盤面のマスに入るのは uid・難易度・解除済みか・誰が挑戦中かだけ
- 説明文は「その人がいま開けているコード」のぶんだけ `privateFor` で配る
- 大画面には公開情報だけを渡す（`privateFor` が null を返す）
- 対戦記録にもお題の名前を残さない（記録画面は誰でも開けるため）
- テストで「秘密が公開情報に混ざっていないか」を必ず確認する（`tests/realtime-bomb.js`）

### 答え合わせ（第45弾 45-6）

決着したあと、結果画面の「🔍 答え合わせを見る ›」で、コードごとに
**問題／正解／誰が何と答えたか／合っていたか**を見られます。

- **手渡しと部屋で、同じ1つの部品が描く。**受け取る形も1つに決めてある：
  `[{ tier, question, name（正解）, solved, tries:[{ name, answer, correct, at }] }]`
  （`at` は**コードをまたいだ答えの順番**。束ねると束の外の前後関係が消えるので、
  　「最後に決めた人」を出すのに要る——無いと盤の並び順を時間だと読み違える）
- 協力版は `tries` が全員ぶん（盤面を共有しているので公開情報）。
  **競争版は自分のぶんだけ**——同じコードに全員が別々に挑むので、他人の答えは秘密のまま。
  公開ビュー（大画面もこれを見る）には、誰の答えも入りません
- 手渡しは `tries` に名前が入りません（1台を回すので、誰が押したか分からない）
- **並べ替えない・点数で色を変えない。**合っていたかは ✓ / ✕ の**形**で出す
- 褒める印は 🎯（よく当てた）と 🔑（最後に決めた）。名前が無い遊び方では出しません
- 「だれも答えませんでした」と言うのは、**答えの記録が届いている時だけ**。
  競争版を横から見ている端末には誰の答えも配られないので、そこで言うと嘘になります

サーバー側は挑戦の記録（`room.bomb.log`）1つだけを持ち、
45-4（だれが外したか）と 45-6（答え合わせ）の両方がそれを読みます。

> 下の記述は、AIで説明文を作っていた第27〜31弾の形です（`prepare()` は残っていますが呼ばれません）。
>

> 遊んだ人が「書いてあることと違う」と言うまで3年気づきませんでした。

部屋で始めると、まず `prep` の段階に入り、サーバーが全コードの説明文を作ります。

- 同時実行は3本。多いとレート制限に当たり、少ないと待ち時間が伸びる（30本で10秒前後）
- 1本ごとに失敗したら1回だけやり直す。APIキーが無いなど、やり直しても直らない失敗はその場でやめる
- 何度やっても作れなかったコードは盤面から外す（開いても答えようがない「死んだコード」を置かない）
- 1本も作れなかった時は、始まらずに理由を出す（行き止まりにしない）
- 待合には「2 / 6本」のように**本数だけ**を出す。中身は1文字も出さない

### お題プールの受け渡し（第46弾で無くなった）

**もう渡していません。** 第32弾-A-3-6 で問題バンクに切り替わってから、
コードの3択は問題バンクが自分で持つようになり、受け手（bomb-room.js）は
渡されたお題を `const topics = []` で捨てていました。
それでも進行役の端末は、試合のたびにお題プールを丸ごと送り続けていました。
第46弾で、送る側も受ける側も消してあります。

※ ここは落とし穴33（表示している約束は実装より長生きする）の典型でした——
`bomb-logic.js` には「説明文はもう作らない」と書いてあるのに、
その隣を通る道だけが3年ぶん残っていました。

### 残り時間の配り方

残り時間は「あと何ミリ秒」で配り、端末側で減らします。
期限（時刻）をそのまま配ると、時計がずれている端末で残り時間が狂うためです。

競争版は人それぞれ期限が違うので、`room.bomb.deadline` には
**いちばん早い期限**を載せて `realtime.js` の時間切れ監視に見せています。

## ゲーム：同時解除（さらに次のフェーズ・未実装）

### 全体ルール

- 協力型・競争型の2種類。**両方とも部屋を立てるのが必須**
- 協力型：「共通タイマーで片方が遅れるともう一方も巻き込まれる」（上級者向け任意設定、デフォルトOFF）と
  「特定ボタンは両チーム同時押しが必要（残り15秒以内には出現しない）」の両方を実装
- 競争型：先に解除されたチームが出た時点で、まだ解除中のチームは即座に爆発
- 各チームに配る爆弾を変える：**競争型は同じ爆弾**（条件を揃えて純粋な速さ比べにする）、
  **協力型は別の爆弾**（互いに違う状況だからこそ緊張感が出る）

### チーム編成ルール（確定）

1. 人数が偶数なら、2人1組（解除役＋マニュアル役）でペアにする
2. 人数が奇数なら、原則は全員ソロ。ただし9人以上かつ3で割り切れる場合だけ、3人1組に切り替える
3. チームは必ず2つ以上
4. チームサイズは全チームで統一する（一部だけペア・一部だけソロ、という混在はしない）
5. マニュアル役だけのチームは無効。解除役は必ず1人以上必要

### チーム構成画面のUI（イメージ確定）

- 画面上中央に大きく「チーム構成」の見出し、現在の人数
- 部屋番号を表示
- 「QRコードを表示する」ボタン → 押すと画面全体にQR、背景は黒
- 「未割り当て」：部屋に入ってきた人はまずここに表示される
- 「チームA」「チームB」…：それぞれのメンバーを表示
- 人をドラッグ＆ドロップで、未割り当て⇄チーム間、チーム⇄チーム間を移動できる
- 「チームを追加する」ボタンで手動でチームを増やせる
- 「自動整理」ボタン（「準備完了」より控えめな大きさ）：
  **単押しなら未割り当ての人だけ振り分け、長押しなら既に配置済みの人も含めて全員組み直す**
- 「準備完了」ボタン（一番目立つ大きさ、全員が押すまでスタートしない）

**マニュアル役の決め方**：マニュアル設定がONの場合、チーム構成の「準備完了」の後、
**チームごとに「マニュアル役を決めよう」画面（そのチームのメンバーだけに表示）**を挟みます。
チーム内で相談して選び、もう一度全員が「準備完了」を押してから試合開始。
**ソロチームには、この画面自体を出しません**（マニュアル役を選びようがないため）。
1段階目のボタンラベルは、マニュアル設定の有無で「スタート」／「つぎへ」と変えます（混乱を避けるため）。
