# 監査：実機チェックリスト（第35弾D・くまくんへの依頼）

検証環境（ブラウザ自動運転）では再現できない、**実際のスマホでしか確かめられない項目**だけを残したリスト。
それ以外の異常系はすべて自動検証済み（`tests/abnormal.js`・`docs/監査_異常系シナリオ.md`参照）。

## 1. スリープ→復帰（d05）——スマホ2台以上で

準備：スマホ2台＋PC等でもう1人（計3人）で部屋を作り、ワードウルフを開始して**投票の画面**まで進む。

- [ ] A. スマホ1台を**画面ロック（スリープ）**して2〜3分放置 → 残りの端末に「◯◯さんが席を外しました」系の表示が出るか
- [ ] B. スリープ中に残りの2人で投票を済ませる → **スリープ中の人を待たずに**結果へ進むか（自動検証済みの挙動が実機でも同じか）
- [ ] C. スリープから復帰 → 画面が**いまの状態**（結果 or 次の段階）に自動で追いつくか。
      追いつかない場合、リロード→部屋コード＋同じ名前で入り直して復帰できるか
- [ ] D. 復帰した画面の**自分のお題・役職が正しい**か（前の段階の古い表示や、他人の情報が出ないか）
- [ ] E. スリープ直前に押しかけたボタン（押した瞬間にロックした等）が、復帰時に**二重に効いていない**か
      （票が2票になっていない・「もう投票済みです」等で正しく断られる）

補足：Bの間にホスト端末をスリープさせるパターンも1回試せると理想（→残りの端末に「進行役が◯◯さんに移りました」
相当の変化が起き、進行が止まらないこと。d03の自動移譲の実機確認）。

## 2. 大画面のピクセルの見栄え（フェーズCの持ち越し）

検証環境ではテキスト・構造の確認まで（描画フレームが取得できない）。TVやモニタに映した時の**見た目**だけ確認：

- [ ] 部屋の大画面表示をTV/モニタに映し、以下を1〜2ゲームで流し見る：
      文字が遠くから読めるか／レイアウト崩れ・はみ出しがないか／
      爆弾解除の横棒グラフ・クイズの伏せ字・決着表示が綺麗に出るか
