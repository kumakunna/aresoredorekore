## 44-1 の原因（着手前の調査）

**再現**（`tools/dev-server.js` + `/dev-login`・375×812）：
棚で「4人」→ 人狼 →「1台のスマホで」→ 人狼 → つぎへ → モード画面。

| 画面 | 実測 |
|---|---|
| 棚のチップ | `👥 4人　▾`（`localStorage['acac-heads'] = "4"`） |
| `scr-setup` | **2**（`nameRows` の行数も2） |
| `scr-mode` | 6モード全部 `locked`。`カジュアル人狼 / 3人以上で遊べます（いま2人）` |

モード画面に着いた時点で `headsProbe()` は `{heads:4, 見当:4}` を返していた。
**チップの値は生きていて、誰も読んでいなかった。**

**「2」の出どころは、プレイヤー登録画面の手書きの `2`**
（`enterSetup()`。初期値でも、別の変数でも、部屋の人数でもない）。
値の流れが棚とモード画面のあいだで切れていた：

| 誰が | 何を読む | 届く先 |
|---|---|---|
| 棚のチップ | `headCount()` | 棚の中の4関数だけ |
| 登録画面 | どこも読まない。`2` を直書き | `state.players` |
| モード画面 | `state.players.length` | 「いま2人」 |

### 原因を追ううちに出てきた同じ根の3件

**（a）人数の数え方が3つ並走していた**（落とし穴1・20）

| # | 数え方 | 使う所 | 大画面 | 切断中 |
|---|---|---|---|---|
| 1 | `headCount()` | 棚のチップ・沈み具合・理由 | **数える** | **数える** |
| 2 | `state.players.length` | モード画面のロック・`guardMinPlayers` | — | — |
| 3 | `room.playerCount`（サーバー） | 待合だけ | 除く | **数える** |

※ 3 の「切断中」は当初「除く」と報告したが誤り。`playerMembers()` は
`role === 'player'` だけで絞り、`connected` は見ない（`realtime.js:299`）。
退室・kick は `members.delete` で名簿から消えるので、そちらはちゃんと減る。
**それでよい**——電波が切れた人も、その場の椅子には座っている。
`readyTally` が `connected` で数えるのは「準備OKを押せる端末があるか」という
別の問いで、それを「何人いるか」に持ち込むと、
トンネルに入った1人で人数が点滅する。

**（b）`headCount()` の部屋分岐が、存在しない項目で絞っていた**（落とし穴9）

```
rt.state.room.members.filter(function(m){ return !m.gone; }).length
```

`publicSnapshot` が配るメンバーの項目は
`id / name / role / connected / isHost / icon / title / ready` の8つで、
**`gone` は一度も送っていない**。`gone` を持つのは `sugoroku-room.js` の
ゲームデータだけ——**すごろくの世界の言葉が、棚の人数計算に漏れていた**。
フィルタは素通りなので、実体は `members.length`（TVにした端末も数える）。
同じ式のコピーが `scr-room-open` の「参加者：◯人」にもあった。

**（c）部屋では、モード画面が人数を一度も出していなかった**

`modeLockReason` が `!goingRealtime()` で人数の行ごと素通りしていたので、
進行役には「4人いる」と分かる場所がどこにも無かった（門G4 の前提が崩れていた）。

### 直し方

**新しく数えるのではなく、既にある3つを1つに寄せる**（`currentPlayerCount()`）。
一番確かな数を優先する：

1. 部屋がある → `room.playerCount`（サーバーが数えた数）
2. 手渡しで登録済み → `state.players.length`
3. どちらも無い → 棚のチップ（見当）
4. どれも無い → 0（＝まだ答えていない。**止めない**・第41弾 2-3）

**部屋ではカードを押せなくしない。** 指示37の「人が集まる前に進行役が
決めておける」を壊すので、人数は `modeRoomNote` の1行に出し、
足りないことは待合が見張る。

### G5：人数が変わると追随する（モード画面に居たまま）

| 操作 | 画面の「いま◯人」 | サーバーの `room:peek` |
|---|---|---|

**画面が言う数と、サーバーが数えた数を突き合わせた**（落とし穴28：
測る側が壊れていないかを1つ測る）。画面を移動せずに追随している。

切断だけで試すと「減らないのが正しい」のに「追随していない」と読んでしまう。

### G13：実機でしか分からないこと（**未検証**）

| 何 | なぜ手元で見られないか |
|---|---|
| **部屋ゲスト面の「いま4人」** | 同じブラウザの2つ目のタブは `localStorage` を共有するので、2人目の別人になれない（実測：2つ目のタブが1人目の `memberId` を引き継いだ）。bot は画面を持たないので代わりにならない。**論理は `tests/mode-screen.js` と実装で押さえたが、実機2台での確認は未検証** |
| グラデーションの見え方 | 32px の溶け具合が「線に見えないか」は、実際の画面の輝度と視野角による |
| 丸い戻るボタンの押しやすさ | 36px は指の的として足りるはずだが、実際に片手で押した感触は未検証 |
| 長押し450msの体感 | 棚と同じ値にそろえたが、モードのカードは棚より縦に狭い |
| iOS の長押しメニュー | `-webkit-touch-callout:none` は Safari だけが見る指定なので、**手元の Chromium では効いているかを確かめられない** |
| 下部バーと iPhone のホームバー | `env(safe-area-inset-bottom)` は手元では 0 |
