## 47-1 の再現と切り分け（指示 §1 の必須項目）

### 測る前に、測定そのものを確かめた（落とし穴28）

ブラウザ枠が裏に回っている間は、`document.timeline.currentTime` が **0 のまま**で、
`getAnimations()[0].playState` が `"running"` でも `currentTime` は動かない。
**つまり画面の演出は全部 0% で止まって見える。**
`.bomb-boom` を測ったら `opacity:0` / `transform:scale(.25)` のままで、
危うく「閃光が出ていない」と報告するところだった。

| 測ったもの | 枠が裏 | 枠が表 |
|---|---|---|
| `setTimeout(60)` | 62〜724ms（不安定） | 65ms |
| `requestAnimationFrame` | **一度も来ない**（-1） | 0ms |
| 使い捨てキーフレームの `currentTime` | **0 のまま** | 進む |
| `.bomb-boom` の `opacity` | **0 のまま** | 0.91 → 0.16 → 0.003 |

**長押し（`makeHoldButton`）は rAF で刻むので、シムを入れないとゲームが始まらない。**
手渡しの再現では `requestAnimationFrame = cb => setTimeout(cb, 16)` を入れた
（中身は本物のまま・時計だけ差し替え。使ったので明記する）。

### 落とし穴26 は、この画面では効いていない

`.app` は `filter:brightness(var(--screen-bright))`（`public/index.html:100`）を常に持つので、
**`#app` は `position:fixed` の含みブロックになる**——条件は成立している。
そして FxKit は `FxKit.init({ root: el('app') })`（22381）なので、
**閃光・帯・コールアウト・紙吹雪・巨大カウントダウンは全部 `#app` の中**にいる
（第39弾で外へ出したのは UiKit だけ）。

だが**実測では、いまずれていない**：

| 何 | 実測 |
|---|---|
| 375×812 の爆弾盤面（コード30本）での `#app` | `0,0 375×812`（`scrollHeight` も 812） |
| ページは本当にスクロールするか | **しない**（`scrollTo(0,3000)` → `scrollTop` 0） |
| `documentElement.scrollHeight` | 871（**ブラウザ枠の実寸。はみ出しではない**・落とし穴45） |
| 同じ CSS の検体を `#app` に入れた時 | `1,0 373×812` |
| 同じ検体を `body` / `#uiLayerRoot` に入れた時 | `0,0 375×812` |

差は**枠線の1pxだけ**。`#app` が `min-height:100vh` かつ `max-width:460px` なので、
スマホ幅では画面とぴったり重なる。

**ただし残っている危険は2つある**（どちらも今回の原因ではない）：

1. `#app` が画面より高くなる画面（設定・記録・カタログの類）で演出を出すと、落とし穴26 の形でずれる
2. **画面が 460px より広い時**（TV・PC）、`#app` は中央 460px の柱なので、
   **「画面全体が赤く光る」は中央の柱だけになる。** 47-6 で大画面に全画面の演出を足すなら、ここは先に直す必要がある

### 指示が挙げた3候補の切り分け

| 候補 | 判定 | 根拠 |
|---|---|---|
| (a) `rtBombPrev` の初期値・更新順で遷移を見逃す | **一部あたり。ただし主因ではない** | 競争版の爆発は `rtBombFeedback`（15060）の遷移判定にしか無く、そこは「解除中」分岐（14904）からしか呼ばれない。`--late` の 0 と `--reversed` の 2 は、まさにこの型 |
| (b) `goTo` や `stageClear` が帯を消す | **反証** | `goTo`（9493〜9613）は演出を1つも掃除しない（実測：帯は画面が変わっても自分のタイマーで消えるまで残る）。`stageClear` は「棚にもどる」と「ゲームを終了」でしか呼ばれない |
| (c) `fxSpeed=skip` / `fxShake=OFF` で消えている | **反証** | 初回の安全案内は両方ON（✓）が既定で、実測で `#app` の class は `app theme-bomb` のみ（`no-flash` も `no-shake` も無い） |

### 主因（3つ）

1. **競争版が、決着の分岐から締め出されている。**
   決着の演出は `renderRtBomb` の `ended` 分岐（14890〜14896）と大画面の `rtBigFx`（14386〜）にあるが、
   どちらも `r.mode === 'coop'` で弾く。競争版の爆発は `rtBombFeedback`（15060）にしか無い。
   ところがサーバーは**最後の生存者が脱落した瞬間に同じ tick で ENDED にする**
   （`bomb-room.js:601` → `finish` 603）ので、その端末は「解除中」を一度も描かずに `ended` へ入る。
   → **誰の画面にも爆発が出ない。**

2. **「解除中を見ていたか」を `rtBombLive` という遷移の記憶で持っている。**
   `rtBombLive` に代入するのは3か所（14752 の初期化・14891・14902）だけで、
   「解除中」分岐を一度も通らなければ false のまま。再接続・途中参加・privateFor の遅れで 0 になる。

3. **落とし穴18の順（秘密が先・部屋の知らせが後）だと、二重に出る。**
   `--reversed` で爆発が 2 個。

**どれも「遷移で判定している」ことが根っこ**なので、指示47-1 の
「事実で判定する（`failed` が真で、まだ出していないなら出す）」に揃えれば3つとも塞がる。

## 47-2 の材料：大画面が到達しうる画面と出口

## 着手後の記録（2026-09-13）

### 段階1：画面いっぱいの演出を #app の外へ出した（`a030eae`）

本人の指定で、47-1 より先にこれをやった。
理由：47-6 で大画面に演出を足したあとだと、見え方をもう一度全部測り直すことになる。

**実測（1280×800・実ブラウザ）**

| 何 | 前 | いま |
|---|---|---|

| `.bomb-boom` の親 | `#app` | **`uiLayerRoot`** |

**置き場は2つに分けた。** `host()`＝揺らす箱（`#app`）／`layer()`＝重ねる層（`#uiLayerRoot`）。
**`shake` だけは `#app` のまま**——層を揺らしても盤面は1pxも動かない。

**安全の門は `:root` へ移した**（落とし穴27）。移した先に写すのではなく、
両方の親に1つだけ置く。先例は `:root.fx-skip`・`:root.fs-*`。
実ブラウザで確認：光の点滅を切ると閃光を作らない（0件）／JSの門を戻しても CSS が `display:none`。

**副産物**：層の中の絵文字が Twemoji に差し替わっていなかった
（第39弾でダイアログを外へ出した時から、ずっとそうだった）。掃く先を `body` に広げた。
