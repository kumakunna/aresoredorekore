## 48-1：ルール・準備OKの画面が出ない時がある（原因の特定）

### 結論：原因は1つではなく、**独立した3つ**。どれも「ランダム」に見える

指示は「(a) ready が残る／(b) 放送の順序／(c) 2回目／(d) 手渡しの永続化」を候補に
挙げていたが、**実際に効いていたのは (d) と、候補になかった2つ**だった。

#### 原因①（本命）：「読んだか」を数える鍵が、**経路によって変わる**

鍵は `rtRulesKey()` ＝ `モードid ?? ゲームid`（`public/index.html:11304`）。
そのモードidは部屋の `state.data.modeId` に載っている。

ところが `clearGameState()` は **`room.state.data = {}`** にする（`realtime.js:76`）。
`pickGame` を呼ぶ5か所のうち、**`data:{modeId}` を渡しているのは
`backToRoomWithGame`（`11266`）ただ1つ**。再戦（`21710`）・強制終了（`22417`）・
えらび直し（`21716`）は渡していない。

**本物のサーバーで実測**（`tests/room-edge.js` の `startTestServer` で `realtime.js` を起動）：

| 遊ぶ人の操作 | 部屋に載る `data.modeId` | 「読んだか」の鍵 |
|---|---|---|
| 棚 → 協力版をえらぶ | `bomb-coop` | **`bomb-coop`** |
| 二人とも準備OK → はじまる | （消える） | `bomb` |
| **「もう一度」（再戦）のあと** | **無し** | **`bomb`** |
| **「みんなを待合にもどす」のあと** | **無し** | **`bomb`** |
| 競争版にえらび直した | `bomb-race` | `bomb-race` |
| また協力版をえらんだ | `bomb-coop` | **`bomb-coop`** |

同じ「クイズ解除・協力版」を遊んでいるのに、**記憶が `bomb-coop` と `bomb` の
2つに割れている。** どちらが使われるかは「どの道でそのゲームに来たか」で決まり、
遊ぶ人の画面には何の違いも出ない。

- **出すぎる向き**：再戦すると鍵が `bomb` に変わるので、
  2周目なのに全員がルール画面へ引き戻される（設計は「2周目には出さない」）
- **出ない向き**：いちど `bomb` で準備OKを押すと、以後その部屋で
  `bomb` を鍵にする経路（再戦・強制終了あと）ではルールが二度と出ない

#### 原因②：部屋の画面の外にいる人は、**引っぱられない**

`rtSync` は `RT_SCREENS.indexOf(cur) === -1` で早く帰る（`13024`）。
戻ってきても `enterRtRoom()` は描き直すだけで、いるべき画面を計算し直さない（`11478`）。

**jsdom で実測**（対照実験つき。落とし穴10-b）：

| | 待合にいたまま選ばれた | ⚙→アプリの設定→アイコン・二つ名（`scr-titles`）に出ている間に選ばれた |
|---|---|---|
| ホストが選んだ直後 | `scr-rt-rules`（出た） | `scr-titles`（動かない） |
| 自分で待合にもどったあと | — | **`scr-rt-room`（ルールが出ないまま）** |
| 待合の「準備OK」 | — | **押せる（＝読まずに押せてしまう）** |

`scr-titles` は待合から⚙で普通に行ける画面。**遊ぶ人には「自分の二つ名を見ていたら
ルールが出なかった」としか見えない。**

#### 原因③：進行役の初回ルールは、**端末に永久保存**されている

`finishWizard()` が見ているのは `state.seenRules[modeId]`（`10809`）。これは
`localStorage['aresoredorekore-prefs']` に入って**永久に残る**
（`8164` 初期化・`8440` 読み込み・`8451` 保存・`17014` 立てる）。

つまり **その端末で一度でも遊んだモードは、別の日・別の部屋でも二度と説明が出ない。**
ゲスト側は `rtRulesSeen`（メモリ・部屋を出たら忘れる、`11292`）なので、
**同じ部屋の中でホストとゲストで寿命が違う**（落とし穴1）。
45-3 でルール文を書き換えた時、既読の人が新しい文を一度も見ないまま遊んだのはこれ。

#### 原因④（設計上の穴）：「キャンセル（あとで押す）」が既読の印を立てる

`11605`：進行役でない人が「キャンセル」を押すと `rtRulesSeen[key] = true`。
一度でも後回しにすると、その部屋ではもう説明画面に引き戻されない。

### 「ランダム」の正体

**4つとも、遊ぶ人の画面には手がかりが出ない。**
①は「どの道で来たか」、②は「その瞬間どこを見ていたか」、③は「その端末の過去」、
④は「前に一度押したかどうか」で決まる。どれも本人には見えないので、
「出る時と出ない時がある」としか感じられない。

## 48-2：3カセットの全場面

**285場面**を洗い出した（オークション・すごろく5・クイズ王4 × 部屋／手渡し／大画面）。
進行役7本すべてが `PHASE` を輸出しているので、**「全場面」は手書きせずコードから導ける**。
ただし段階はゲームごとに違うので、掛け算にすると通らない段階まで「帯が無い」と赤くなる（落とし穴10-b）。
実際に通る段階は、進行役を動かして数えた：

| ゲーム | 実際に通った段階 |
|---|---|
| auction | preview → bid → confirm →（落札されたら）guess → reveal → ended |
| sugotoll | ready → turn → result → ended |
| sugograb | ready → mini → play → grab → result → ended |
| sugopair | ready → roll → split → result → ended |
| sugohide | ready → turn → say → judge → result → ended |
| sugohand | ready → offer → buy → turn → result → ended |
| quizrush / quizlist / quizreveal / buzzer | play →（rush と buzzer だけ break）→ ended |

**版の有無もデータから導ける**——`MODES[].roomOnly` と `SugorokuLogic.GAMES[].handoff`。
この3カセットで生きている手渡し版は **sugotoll / sugograb / sugopair の3つだけ**。
オークション・早押し・クイズ王決定戦の手渡しモードは `hidden:true` で棚に出ていない
（`modesForGame` `5999` と `visibleModes` `10026` が `!m.hidden` で外す）。

**帯の置き場**：`.rt-phase` ＋ `.rt-public` があるのは4画面（`scr-rt-play` / `-bomb` / `-defuse` / `-quiz`）だけ。
オークション6画面とすごろくには無いので、共通の器を1か所から差し込む形になる。

### 「書けない」は2種類ある。分けて扱う

68件が「書けない」だったが、**性質がまったく違う2つが混ざっている**。

- **(A) そもそもその場面が無い**（41件）…`roomOnly` で手渡し版が無い／その段階に到達しない／
  その立場が構造的に作れない。**ルール変更の話ではない。** 台帳に「帯は要らない・理由」と書く行になる
- **(B) 1行で書くと嘘になる／主語が決まらない**（27件）…**これがルール変更候補**
