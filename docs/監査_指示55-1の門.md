## 判断①：早押しの bracket を、部品A（1v1の同時マッチング）の土台にできるか

### 結論：**(B) 別部品にする。**

**bracket との違い（1行）**

> **bracket は「勝った人だけが次へ上がる木を、1組ずつ順に消化する」。
> 部品Aは「その回にいる全員を一斉に組にして、同時に回す」。**

### そう判断した理由

| # | 理由 | 根拠 |
|---|---|---|
| 1 | **進行の形が正反対で、`matchIndex` が意味を失う。** bracket の芯は「いまのラウンドの何試合目か」を指すカーソル1本。同時回しではこれが常に 0 のまま使われない死に変数になる | `public/js/quiz-logic.js:281-287`（`b.pairs[b.matchIndex]` を1つだけ返す）・`:296`（`b.matchIndex++`） |
| 2 | **呼び出し側が全部「1試合ぶん」で書かれている。** `w.buzzer` の9つのフィールド・`publicView`・`privateFor`・大画面の「A（n） VS B（n）」の1行が、どれも単数前提 | `quiz-room.js:351-363`・`:510-533`・`:572-581`／`public/index.html:16247-16251` |
| 3 | **入力の形が違う。** bracket の入力は flat な ids。部品Aが要る「同ランク同士」はキーで束ねた集団、「過去の相手を避ける」は履歴。`buildPairs` に引数を足すと、早押し側が一生使わない引数を抱える | `public/js/quiz-logic.js:240-250` |

### ただし「手本は bracket ではない」——すごろく「ふたりでひとつ」が既にやっている

着手前の調査でいちばん効いた発見。**同時に複数の組を回す部屋は、もう1つ実在する。**

- `sugoroku-room.js:1427-1440`（`startRoll` / `startSplit`）が**部屋の `w.deadline` 1本で全組の段階を揃える**
- 待ち人は `sugoroku-room.js:873-877` が
  `livingGroups(room).filter(g => !w.locked[g.id]).reduce((acc, g) => acc.concat(g.members), [])`

つまり「同時回しだと部屋の時計1本では書けない」は**誤り**。
正しくは「**早押しは組ごとに締め切りがずれるから1本では書けない。全組の段階を揃えるなら1本で足りる**」
——後者こそロシアンカードが採る形。**部品Aの設計の手本は、bracket ではなくこの pair 進行。**

### 「勝ち抜きと同時回しは1つの正本から」（落とし穴1）をどう満たすか

**いまの正直な姿：同じことをする実装が、既に3つ並走している。**

| 実装 | 何をする | 奇数の扱い |
|---|---|---|
| `QuizLogic.buildPairs` / `newBracket`（`public/js/quiz-logic.js:240`） | 勝ち抜き・1組ずつ順に | **不戦勝**（`[id, null]`） |

**奇数の扱いだけで3通り。** 部品Aを何も考えずに足すと4つ目になる。

**やること**

1. **`buildPairs` を部品Aへ移し、`quiz-logic.js` は部品Aから借りて再エクスポートする。**

3. `shuffled` は**現状13か所に重複している**。部品Aで14個目を作らない

> **`rank` は「順位付けの正本」と呼べない。**

## カードの絵柄（通常版・4種の案）

**作りは「SVGは地紋と枠だけ・意味はHTMLで重ねる」の二層。**

```html
<button class="btn rc-card" data-i="4" aria-label="4ばんめ">
  <svg class="rc-face" viewBox="0 0 90 120" aria-hidden="true"> …地紋と枠だけ… </svg>
  <span class="rc-mark">💣</span>       <!-- 絵文字。既存の差し替え経路にそのまま乗る -->
  <span class="rc-word">ばくだん</span>  <!-- 文字。ui-text-scan の「HTMLの地の文」層で拾われる -->
  <span class="rc-no">4</span>
</button>
```

二層にする理由は2つ。

1. **インラインSVGの中に絵文字を置くと壊れる。**
   `public/js/emoji.js:189` の除外は `script` / `style` / `textarea` / `title` の4つだけで、
   **SVG の `<text>` が入っていない。** MutationObserver が SVG 名前空間の中に HTML を挿し込む
2. **SVG の presentation attribute には `var()` を書けない。**
   リポジトリ全体に `fill="var(` / `stroke="var(` は1件も無く、
   既存2例（`.hold-track` / `.sugo-path path`）はどちらも**CSSの規則側**で当てている

| # | 種類 | 構図（viewBox `0 0 90 120`＝3:4） | **色を全部抜いても分かる印** |
|---|---|---|---|
| ① | **裏**（まだめくっていない） | 外周に**二重の枠**（4px と 7px）／面いっぱいに45度の斜線6本（`stroke-width:2`）／中央に一辺18の菱形（輪郭だけ） | **斜線の地紋がある**のは裏だけ |
