### 1-1. `'parity'` は「起きない想定」ではない。**同じ段に奇数人いれば毎回起きる**

指示書2-5 は「起きない想定だが、起きるかどうかを着手前に確認」と書いている。**起きる。**

| 分布 | parity |
|---|---|
| 全員最下段・3人／5人／7人 | **毎回1人** |
| 全員最下段・4人 | 0人 |
| 1段3人・3段3人（6人・偶数） | **毎回2人** |

部屋は3人以上（指示書0）なので、**いちばん小さい部屋で必ず起きる**。
「何も動かない回」が3人に1人、毎回出る。

**ただし「0 にはできない」ではない。**部品Aは `余りの吸収:'trio'`（`versus.js:114`・`:131`・`:205-212`）を
持っていて、渡すと parity は**完全に消える**（検算8）：

| 分布 | `'bye'` | `'trio'` |
|---|---|---|
| 3人・全員同じ段（各2000回） | parity 2000人 | **parity 0人**・3人組2000件（**段をまたいだもの 0件**） |
| 5人・全員同じ段 | parity 2000人 | **parity 0人**・段をまたいだもの 0件 |
| 6人・段1に3人＋段3に3人 | parity 4000人 | parity 0人だが、**3人組4000件のうち 1494件（37%）が段をまたいだ** |

`:208-210` が `組[i % 組.length]` と**番号だけ**で吸収先を選ぶため、段が割れていると
**段1の人が段3の組に入る**。さらに3人じゃんけんは勝敗規則が違うので、2-2 の6条件が書けない。
**それでも「同じ段に奇数人」という、いちばん起きる形では段をまたがない**ので、
選択肢として本人の前に出す（9節 論点①）。

### 1-2. 希望が**非対称**なので、部品Aが「組めるはずの1組」を消す

`versus.js:156-162` は「候補ゼロ＝どの段階でも候補が空」を **greedy の前に名簿全体で判定し、
その人を `組める` から外す**（`:165`・`:177-178`）。
①の希望（全体から・同ランク）は**対称**なのでこれで正しい。**②の「1つ上」だけが非対称。**

実測（検算2）：

```
段5に1人（Y）・段6に1人（X）
  2段希望（指示書のまま） → 組=[]   相手なし=[Y:no-candidate, X:parity]
  3段希望（1つ下を追加）  → 組=[{a:Y, b:X, 理由:'1つ下'}]   相手なし=[]
```

**X が Y に挑む、という②がいちばんやりたい1組が消える。**
しかも②は Y にAIを出し、X には何も起こさない——**両方とも間違い**。
「段0に2人・段1に1人・段2に1人」のような、ごく普通の途中盤面でも起きる。

### 1-3. **決着の 62〜99% が「AIに勝って優勝」**（この調査でいちばん重い数字）

構造的にそうなる——2-2 は挑戦者がチャンピオンになることを禁じている（1つ手前で止まる）ので、
優勝は必ず「最終段で1勝」。ところが最終段にいるのはふつう1人なので、
**同ランク0人・1つ上0人＝`no-candidate`＝AI**。

実測（検算7・各500局。「決着がAI戦」＝最終段へ上がった1勝がAI相手だった局の割合）：

| | 3人 | 4人 | 6人 | 8人 | 12人 |
|---|---|---|---|---|---|
| **通常版5段・2段希望** | 90.0% | 93.8% | 78.8% | 73.6% | 61.8% |
| 通常版5段・3段希望 | 18.0% | 1.2% | 0.0% | 0.0% | 0.0% |
| **通常版6段・2段希望** | 95.6% | 97.2% | 90.2% | 83.6% | 72.4% |
| 通常版6段・3段希望 | 27.0% | 5.6% | 0.2% | 0.0% | 0.0% |
| **CS版10段・2段希望** | 98.8% | 98.8% | 98.2% | 98.0% | 95.2% |
| CS版10段・3段希望 | 51.2% | 28.6% | 16.0% | 7.4% | 2.2% |

**遊ぶ人は、誰もいない相手に勝って優勝する。**しかも 2-2 は「AIであることを知らせない」。

> （落とし穴28）。`tools/probe-evo-crosscheck.js` の冒頭にこの注意を書いてある。

#### この数字は**下限**（あいこを振り直していないため）

`tools/evo-preflight.js` は振り直す形で回していて、そちらは **95.7〜100%** と出る。
**どちらの模型でも向きは同じで、振り直す方が悪い。**

### 1-4. `理由:'1つ上'` の印は、「**1人ランクの人**」を意味しない

指示書2-2 は「1人しかいないランクの人」に3つの特典（勝てば2つ上・負けても落ちない・連敗も数えない）を与える。
その人を見分ける印として `組.理由` を使いたくなるが、**使えない**。

実測（検算5・各2000局）：

| 分布 | 「1つ上」の組 | うち挑戦者に**同段の仲間がいた** |
|---|---|---|
| 段1に3人・段2に3人 | 2000件 | **2000件（100%）** |
| 段1に3人・段2に2人 | 402件 | **402件（100%）** |
| 段1に1人・段2に2人（本来の形） | 682件 | 0件（0%） |

機構は `versus.js:183-188`——第1希望の相手が「**空いているか**」だけを見て、
**その段に何人いるかは見ていない**。同段の仲間が先に取られただけの人にも `'1つ上'` が付く。
**このまま実装すると、特典が配られすぎる。**
②は**段の人数を自分で数える**しかない（門U6 の1行目は、そこを検査する）。

### 1-5. `a` が挑戦者、は②が渡す希望に依存する（部品Aの保証ではない）

2段希望では `理由:'1つ上'` の組 12,200件すべてで `a.rank+1 === b.rank`（違反0件）。
**しかしこれは部品Aの性質ではない**——`:195` が `{a: 自分}` と書き、②の希望が上向きだけだから。
現に `tests/versus.js:154` は**対称**な第2希望を書いており、そこでは `a` に上位ランクが入る。
そして**3段希望にすると `理由:'1つ下'` の組ができ、そこでは `a` が上位**（検算2）。

→ **②は `理由` の文字列で挑戦者を決めてはいけない。段の大小で決める。**

### 1-6. `直前の不戦勝` は1人分しか効かない。**配列を渡すと黙って無視される**

`versus.js:169-174` は `idOf(x) === o.直前の不戦勝` の等値比較。実測（検算4）：

```
直前の不戦勝=null           → 余り: ["p6","p2"]
直前の不戦勝="p6"           → 余り: ["p2","p5"]   ← p6 は救われた
直前の不戦勝=["p6","p2"]    → 余り: ["p6","p2"]   ← null の時と同じ＝配列は無視
```

②では余りが2人以上になる回が普通にある（1-1）ので、**「いちばん長く待っている1人」を選んで渡す**しかない。

### 1-7. 「1人ランクは上と当たる」は、約束として守られていない（34〜55%）

`順 = shuffled(組める)`（`:165`）で**先に処理された人が勝つ**ため。実測（検算1・各2000局）：

| 分布 | 上と当たれた率 |
|---|---|
| 下1人 / 上2人（3人） | **34.1%** |
| 下1人 / 上3人（4人） | 100.0% |
| 下1人 / 上4人（5人） | **49.0%** |
| 下1人 / 上5人（6人） | 100.0% |

**第3希望「1つ下」を足しても、この率は動かない**（34.1% のまま。検算1）。
直せる口はある——`:193` が `(好み.length ? 好み : 空いている)[0]` と**先頭**を取り、
候補配列の順序は保たれる（`:141-150`・`:185-187`）ので、
**候補関数の中で「下にいる1人ランクの人を先頭に置く」と 100% になる**（検算6）。
ただし素朴にやると `理由` が `'同ランク'` のまま出る（検算6の内訳）ので、**そのままでは使えない**。

### 3-3. 差分法（門U4）の形

①の「窓」（進行が動く前の1枚を比べる）をそのまま写すと**足りない**。
じゃんけんは相手の手が同じでも自分の手が違えば勝敗が変わり、勝敗が変われば段が変わり、
次の回の `shuffled` が食う乱数量まで変わる。
**正しい形は「開く前の1枚を、9通りの手の組み合わせ全部で比べる」**（進行がまだ動いていないので窓が要らない）。
これなら「どちらが勝つか」「あいこになるか」「相手の手そのもの」の3つを同時に捕まえる。

## 4. 状態と境界の表（`docs/監査_状態と境界.md` に足せる形）

境界は**5種類**。指示書の候補4つに「**段階**」を足した——`setPhase()` が書くものはここでしか消えない。

| 境界 | いつ消えるか | 誰が消すか |
|---|---|---|
| **段階** | `match`→`throw`→`reveal` が切り替わるたび | `setPhase()` 1か所（`rcard-room.js:72-77` の形） |
| **組** | その1v1が決着 or 引き分け | 回戦の作り直しで配列ごと捨てる |
| **回戦** | マッチングをやり直すたび | `startRound()` が `w.matches=[]` から（`rcard-room.js:147-150`） |
