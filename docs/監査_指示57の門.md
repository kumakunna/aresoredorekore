## 2. 判断②：スポットライトの実装方法（実測した）

### 2-1. 測り方と、その健全性（落とし穴28）

`node tools/dev-server.js` ＋ `/dev-login`、ブラウザ枠 375×812。
**本物の盤**（`window.bombCellProbe` が本物の `bombGridHtml` を通す）を本物の `scr-bomb-play` に出して測った。

測る前に、測定そのものを1つ測った：

| | 結果 |
|---|---|
| `setTimeout(60ms)` | 69ms（正直） |
| `requestAnimationFrame` | **一度も来ない**（枠が裏に回っている・落とし穴47） |

→ **当たり判定・座標・computed style は正しく測れる。CSSアニメの見た目は測れない。**
入場アニメ（`.bomb-inside{animation:bombInsideIn .4s}`）が 0% で凍るので、
**落ち着いた状態を測るために `animation:none` を当ててから測った**（使ったので、書く）。

### 2-2. 4案を、2つの条件で当てた

条件は「明るさ既定（100）」と「明るさを動かした（80）」の2つ。
後者では `:root[data-bright] #app > *{ filter:brightness(...) }`（`index.html:109`）が
**`.screen` に乗る**——`scr-bomb-play` は `#app` の直下の子なので、重なりの基準が生まれる。

| 案 | 的が押せる（既定） | 幕が的の上に無い（既定） | 的が押せる（明るさ80） | 判定 |
|---|---|---|---|---|
| ① clip-path で穴 | ✅ | ✅ | ✅ | **採れる** |
| ② CSS/SVGマスク | ❌ | ❌ | — | **不可** |
| ③ 4枚の矩形 | ✅ | ✅ | ✅ | 採れる |
| ④ 的の z-index を上げる | ✅ | ✅ | **❌** | **採れない** |

**② が落ちる理由**：マスクは**塗りだけを切って、指を通さない**。
穴は透けて見えるのに `elementFromPoint` は幕を返した。「見えているのに押せない」——最悪の壊れ方。

**④ が落ちる理由**：既定では**通る**。落ちるのは明るさを動かした人だけ。
`z-index:9999` にしても、幕を層へ移しても駄目だった（`.screen` の filter に閉じ込められる）。
**「たまたま無害な期間がある既定値」そのもの**（落とし穴36）——
ほぼ全員で動くので実装もテストも通り、**スライダーを1目盛り動かした人だけ、チュートリアルが
ゲームを操作不能にする**。壊れる場所（盤）と原因の場所（明るさの設定）が遠い。

> 補足：④ には**もう1つ独立した死因**がある——`.wiz-body{overflow-y:auto}`(`2036`)・
> `.overlay-panel{overflow-y:auto}`(`893`)・爆弾テーマの `.bomb-wire-btn{overflow:hidden}`(`3867`) の3段。
> 明るさと無関係に、的の中に描いた輪や矢印は切られる。

### 2-3. ① と ③ を分ける材料も測った

| 測ったこと | ① clip-path | ③ 4枚の矩形 |
|---|---|---|
| 角丸の穴 | ✅ `path()` の弧で作れる（`CSS.supports` も true） | ❌ 直角のみ |
| 画面の端にはみ出した的 | ✅ 穴が開く | ✅ 開いたが、**負の座標で矩形の計算が崩れやすい** |
| `hidden` で出し入れ | ✅ | ✅（`[hidden]{display:none!important}`・`index.html:101`） |
| 出し入れする箱の数 | **1つ** | 4つ（落とし穴1の的が4倍） |

**①を推す。** 穴が1つの宣言で決まり、角を丸められ、当たり判定も一緒に切れる。

### 2-4. ①を採る時に必ず効く制約（測って分かったこと）

1. **`clip-path` は子も切る。** 幕の子に文を置いたら、穴の中に出せなかった（`tut-kid` がヒットしない）。
   **文・閉じるボタン・光の輪は、幕の「兄弟」にする。**
2. **置き場は `#uiLayerRoot`。** `#app` の中に置くと上の `data-bright` の filter に巻き込まれる。
3. **`#uiLayerRoot` は `pointer-events:none`。** 中に置いたものは**自分で `auto` を立て直す**
   （`.pause-veil` が既にそうしている・`index.html:1313` のコメント）。
4. **テーマは層に届かない（実測）。** `.app.theme-bomb` を当てた状態で
   `#app` は `--paper:#17181B / --ink:#E8EAED`、層は `#EFE8D3 / #24272E` のまま。
   `.ui-layer`(`1330`) と `.overlay-panel`(`893`) は**わざと共通トークンに戻している**（「道具は世界の外」）。
   → **チュートリアルも道具として扱うのが既存の流儀。** ただし正本§1-3 の一覧に
   チュートリアルは載っていないので、**裁定が要る**（6節の問い）。
5. **文字サイズは層に届く（実測）。** `fs-large` で `#app`・層とも `--fs-body:18px`。印が `html` にあるため。
   ただし**`--font-scale` は `.app` にしか無い**ので、層の中で使ってはいけない（静かに1に落ちる）。
6. **スキップは層に届く。** `:root.fx-skip *`(`1451`) が `animation/transition` を 0.001s にする。
   → **幕の出入りは CSS transition に任せれば、スキップの人には自動で瞬時になる**（2-8 の要求どおり）。
   逆に、**手の進行を `fxMs()` で計ってはいけない**——スキップの人は0msで流れて読めなくなる。
7. **重なり順**：層の中は `.ui-dim`110 → `.ui-layer`120 → `.pause-veil`130／トースト130。
   幕は**110より下**に置くと、ダイアログもポーズもトーストも上に出る。
   ただし `#safetyGate` は `#app` の中で `z-index:200`（`958`）なので、**層より上**にいる。
8. **名前**：`FxKit.spotlight` が**既に別の意味**（箱の中で対象に寄る・`fx.js:744`）で存在する。
   同じ名前を使わない。専用の前置き（`tut-`）を付け、`grep ".名前[^a-z-]"` で先客を見る（落とし穴23）。
9. **座標を測る時刻**：`.screen` は遷移中 0.22秒だけ `transform` を持つ（`index.html:192`）。

   さらに盤は**毎描画 `innerHTML` で作り直される**（`20142`・`24956`）ので、

| 2 | `.pk-btn`（3択の1つめ） | 「3つから、こたえをえらびます」 | `tap` | 同上。答えれば切れるか減るかが**その場で**起きる |

### 3-4. 手数が持ち時間を食う実寸

既定は**コード30本／時計180秒**（`9887`・`24997`）＝1本あたり6秒。
3択そのものに制限時間は無いが、**重なりを開いている間も全体の時計は止まらない**。
→ **台本は「読み終わりを待たない」形にする**（押せば消える・`auto` は2秒まで）。
協力版はチーム共通の時計が減り、競争版は `endWhen='first'` で**他人が解き切った瞬間に終わる**。

## 11. 実装して初めて出たこと（記録）

着手前の調べものでは出ず、**手を動かして初めて出た**もの。どれも「緑だから正しい」が危ない形。

1. **返り先を、動かす前に作らないといけない。**
   台本の的がどれも画面に無いと、`手をおく` は**その場で最後まで走り抜けて** `終わる` を呼ぶ。
   Promise を後から作ると、**その回だけ誰も返事を受け取れない**。
   門W9 の検査が返事を待ったまま止まって見つかった——**検査が無ければ、本番で固まっていた**

2. **`querySelector` では的を引けない。**
   画面（`.screen`）は**全部いつでもDOMにいて**、見えていないものが `display:none` なだけ。
   だから `.bomb-lives` は手渡し（`#bombLives`）と部屋（`#rtBombLives`）の**2つとも当たる**。
   先頭を取ると、遊んでいない側の画面を指す。**大きさを持つ最初の1つ**を選ぶ形に直した。
   これで「画面に出ていない」と「そもそも無い」が同じ扱いになり、どちらも「飛ばす」に落ちる

3. **目印は、自分より前の処理に食われる**（落とし穴28の親戚）。
   harness にチュートリアルの逃し口を作る時、種を markup に差し込んで
   `<script src="/socket.io/socket.io.js">` を目印にしたら、
   **上（`tests/harness.js:199`）が room 用のにせ socket に置き換えたあと**で目印が消えていて、
   **27件が「目印が見つからない」で落ちた**。窓ができた直後に置く形へ変えた。
   ——**自分が選んだ目印が、その時点でまだ在るかを確かめる**

4. **`clip-path` は子も切る**（着手前に実測して分かっていたが、実装でも効いた）。
   文・光の輪・閉じるは幕の**兄弟**に置く。入れ子にすると、穴の中に出した文まで消える

5. **2手目が飛んでいた**（実機で2端末をつないで、初めて出た）。
   マスを押した瞬間に次の手へ進むが、**部屋では3択が届くのは往復のあと**——
   その瞬間は `.overlay.show .pk-btn` が0件なので「的が無ければ飛ばす」が効き、
   **いちばん大事な「こたえをえらびます」を飛ばして、ライフの話に進んでいた**。
   2.5秒後には3択が3つそろっていたので、**選択子は正しく、早すぎただけ**（落とし穴18）。

   | | |
   |---|---|
   | 押す前 | `1 / 4`「コードをえらぶと、もんだいが出ます」 |
   | 押した直後 | `.overlay.show .pk-btn` は **0件** → 飛ばす |
   | 2.5秒後 | 3択は **3件** そろっている |

   **jsdom の検査では原理的に出ない**——往復が無いので、的は常に即座にあるか、永久に無いかのどちらか。
   直し方は「猶予（既定2500ms）を置いてから、無いと決める」。
   待っている間は**前の手の穴と文がそのまま残る**ので、
   「押したから問題を待っている」という自然な見え方になる。
   猶予は `init` から変えられる（検査の都合で遊びの数字を縮めない・落とし穴24）。

6. **通し運転が1件見つけた**：`press-feedback` が `.tut-x → 見あたらない` で赤。
   `.tut-x` は `<button>`（＝共通規則で反応する）だが、
   読む先が `['ui.js','fx.js']` の**手書きの一覧**で、`tutorial.js` を見ていなかった。
   一覧は必ず腐るので、`dead-style.js` と同じく**ディレクトリから導く**形にした（落とし穴4）。
   変異57-P で、手書きに戻すと赤くなることを確かめてある。

   **なお、この赤は「終了コード0」と一緒に出た。**
   `npm test` を `| tail` に通していたので、**終了コードが tail のものにすり替わっていた**——
   CLAUDE.md が名指しで警告している事故（落とし穴28）を、そのまま踏んだ。
   ランナー自身は「赤：スイート数・件数・終了コードのどれかが欠けています」と出していた。
   **最後の通し運転は、パイプを挟まずに回す。**

7. **変異が1件素通りした**（57-G）。原因は実装ではなく**検査の側**（落とし穴10-b）。
   「止められた時は『見た』にしない」を `TutorialKit.start` の直呼びで書いていたが、
   印を立てているのは `tutRun` の中なので、直呼びでは**その行を一度も通らず**、
   最後の主張が**自明に成立していた**。呼ぶ道（`聞く` → `動かす`）から入る形に直し、
   対照（最後まで通すと「見た」になる）も足した——
   それが無いと、**いつも印を立てない実装でも**上の主張だけは通ってしまう
