## 4. 門の関数 `allowedTiers()` の置き方

- **定義は `quiz-bank.js`（UMD）に純関数で1つ**：`QuizBank.allowedTiers({nanisore, muri})` → 5層の部分集合（順番は5層の順）。
  quiz-bank.js はサーバーの3進行役（`quiz-room.js:28`・`bomb-room.js:24`・`sugoroku-room.js:32`）と index.html の**両方がすでに読んでいる**ので、端末とサーバーが**同じ1つ**を通れる
- **端末**：`allowedTiers()`（index.html に1つ）が「手渡し・部屋の進行役＝自分の `appPrefs`」「部屋の参加者＝サーバーが配った許可層」を返す
- **サーバー**：`wolf:start` の payload に許可（`tierMix: {nanisore, muri}`）を載せ、各進行役の `startGame` で `w.cfg.allowedTiers` に1回だけ解く。
  **payload に無ければ3層**（古い端末・道具・悪意のある送り手はすべて安全側に倒れる。`tools/fx-probe.js` 等は今のまま動く）
- **バンクの取り出し（`pickQuestions`・`listTopicsOf`）の中には入れない**：`tests/quiz-bank.js:97` が `pickQuestions('muri')` を直に呼び、
  `tools/dump-list-topics.js` が `listTopicsOf()`＝全件として文書を作っている。中で絞ると**黙って縮む**。門は「層を決める呼び手」に置く
- `realtime.js` には層の知識を入れない（落とし穴22）。運び口として使うだけ

## 6. 自分で決めたこと（理由つき・異論があれば止めてください）

1. **置き場所は共通1か所（3節）**。共通にできない理由が見つからなかったため、指示書の推しのまま
2. **門は hidden の3つ（手渡しのクイズ王・早押し・オークション）にも通す**。棚から届かなくてもコードは生きていて、`showHiddenModes` の検査が動かしている。X4 の表は「生きている入口」と「hidden」を分けて数える
3. **クイズラッシュも共通のトグルに従わせる**。「5段階から自分で選ぶ・1〜8点」を名乗るゲーム（`index.html:7414`）で、3節「聞くこと」に当たりうるので検討した。
   OFF だと 1〜3点の3択になるが、**「知っていれば難しい方が得」という駆け引きは残る**ので遊びは成り立つと判断した。
   そのかわり、**ルール文の「5段階」「1〜8点」を許可層から作る**（放っておくと落とし穴33そのもの）。hidden の手渡しクイズ王（`7409`）も同じ
4. **クイズ解除の既定の配分**：`{12,10,6,2,0}` → **`{12,10,8,0,0}`**（ナニソレの2本を hard へ。合計30＝`bombMax` の既定を保ち、目安時間も変わらない）。
   途中で層を OFF にした時も同じ規則（消えた層の本数を許可の一番上へ）を**1つの関数**で、手渡しと部屋の両方が通す
5. **つぎつぎクイズは「お題の無い層を並べない」**。むりのお題は0件なので、子の「むり」を ON にしても、つぎつぎには出さない（データから導く）。
   これで既存の不具合（むりを選ぶと「その難易度のお題がありません」で始まらない・`quiz-room.js:195-197`、落とし穴21）も消える
6. **途中の変更の道**：`realtime.js` に進行役だけが送れる口を1本足し、中身は進行役（`driver.updateOptions` を持つものだけ）へ素通しする。層の意味は進行役の中だけで扱う（落とし穴22）
7. **ゲストが層を送ってきた時は `ok:false` を返す**（黙って ok にしない・落とし穴14）。ラッシュの `634` を許可層と照らす
