## 直したもの・決めたこと（66-1 の中で見つけたもの）

- **字の高さ**：M PLUS 1 は 0.10em 下、League Spartan の数字は 0.14em 上に描かれる（画素で測った）。`.v2 *{text-box:trim-both cap alphabetic}` の1行で ±1px（`tools/v2-ink.js`）。
  ascent-override は Safari が知らないので採らない。**詰めた箱の中の札は箱の下へはみ出す**——TV の帯ののこり時間が安全な枠の外へ出ていたのを check.js が見つけ、端の箱を flex にした
- **中心**：見本は4つのアイコンだけ手でずらしていた。`tools/gen-v2-art.js` が全部（アイコン50・印8）の描かれている所を Chrome で測って viewBox をずらす。道具は見本と同じ4つのずれを自分で見つけ、ほかに20を合わせた
- **1〜2文字だけの行**：ルールの札で「…みんなの／勝ち」が2件出た（check.js）。`V2.fixWraps` がいちばん後ろの文節の切れ目を1つずつ消して直す（全部の画面で効く1か所）
- **重ならない**：部品の見本で、見出しの字が右上の丸ボタンの下にもぐっていた（check.js は測らない）。見出しの右に 100px 空け、撮る道具に「右上のボタンと重なる」を足した（自己検査つき）
- **ルールの番号を3px右**：シートの黒い丸の中の番号は、見本ですでに丸のまん中（横 −0.33px）だった。動かすと「中心」とぶつかるので、**ルールの札の番号を 3px 右**にした。**解釈なので確認がほしい**
- **TVの長い名前**：7割まで縮めると 42px（1280×720 で 28px＝本文の下限）を割る。TV の名前は 42px より小さくしない（`data-v2-fit="42"`）
- **くり返す動き**：新しい見た目は「なし」と「動きを減らす」で `animation:none`（下の「見つけた不具合」と同じ理由）
- **v2 の節のコメントに、制御盤テーマの節の見出しの字を写していた**：smoke.js はその字の1つ目から「テーマ専用」として読むので、v2 の規則を全部「テーマの外」と数えた（1回目の npm test で赤）。
  しかも tests/v2.js の「その節より上にある」は、同じ写しを拾って自明に通っていた（落とし穴10-a・45）。コメントの言い方を変え、確かめを「印の1つ目が v2 の節の後ろ」に直した（変異 66-Q で赤を確かめた）

## 見つけた不具合（66-1 の外・古い画面）

**演出を「スキップ」にすると、古い画面のくり返す動きがチカチカする。**
アプリ全体のスキップ（`index.html` の `:root.fx-skip *{animation-duration:0.001s!important}`）は、長さを縮めるだけで回数を止めない。
`node tools/probe-skip-strobe.js` で本物の CSS のまま読むと、

| 部品 | ふつう（20コマ） | スキップ（20コマ） |
|---|---|---|
| 待っている間の脈 `.fx-alive` | 0.550 → 0.5500 → 0.5502（なめらか） | **0.55 → 0.61 → 0.81 → 0.94 → 0.998**（コマごとに飛ぶ） |
| 爆弾の世界のランプ | 1 のまま | **1 ↔ 0.55 がでたらめに入れかわる** |
| AI を待つ一言・のこりわずかの時計・サイコロの長押し | なめらか | コマごとに飛ぶ |

画面の書きかえ（1秒に60回）ごとに明るさがでたらめに変わる＝チカチカ。正本 §6「点滅は1秒に3回まで」に触れうる。
**スキップを選ぶのは演出が苦手な人**なので、いちばん困る人に出る。直し方は1行（`:root.fx-skip *` に `animation-iteration-count:1 !important`）で、
古い画面の「スキップ」の時のふるまいが変わるので、直してよいかを聞いた。**くまくんの返事（2026-10-23「直してください。先に失敗するテストを書いてから直す」）を受けて直した**：
先に `tests/safety-rules.js` に「スキップでも、くり返す動きがチカチカしない」を足して赤を確かめ（スキップの全体の規則が回数を止めていない）、
本物の Chrome でも `tools/probe-skip-strobe.js` が「5つがチカチカ」と赤を言うのを確かめてから、スキップの全体の規則に `animation-iteration-count:1 !important` の1行を足した。
どちらも緑（「ふつう」では5つとも動いていることも確かめた）。`animationend` を待つ処理はどこにも無い（掃き出して0件）。
