### 3：音のピーク（`node tools/sound-peak.js --no-limit`・2026-10-30）

本物の関数で鳴らした順と時刻を記録し、OfflineAudioContext に本物の音の箱と出口（音量のつまみ → リミッター）をつないで鳴らし直した数。

| 場面 | 鳴らした音 | 3つを超えて鳴らさなかった | ピーク（既定の音量 70） | ピーク（音量 100） | くらべ：音量100・リミッターなし |
|---|---|---|---|---|---|
| ① 16人のみんなと同じの開く（TV） | 17回（tap・cheer） | 0 | −4.92 dB | −2.36 dB | −5.18 dB |
| ② 16人のそろえて発射の点火（ぽてっ＝火の粒がいちばん多い） | 10回（spark・decide・miss） | 2 | −6.48 dB | −2.85 dB | −6.80 dB |
| ②b 16人のそろえて発射（宇宙・歓声まで） | 5回（spark・decide・cheer） | 0 | −6.67 dB | −3.57 dB | −6.99 dB |
| ③ クイズ解除の爆発の幕＋解除の幕＋歓声2つ | 13回（boom・tick・cheer・defuse・tap） | 0 | −4.98 dB | −2.34 dB | −3.12 dB |

- ファイル35本は、どれも mp3 を読みもどしたピークが −3dB 以下（いちばん大きいのは tick-3 の −3.21 dB）。大きさは役ごとの段（爆発 −22・解除／ファンファーレ／歓声 −23・ふつう −26・tap／tick／spark／ng／gavel −29.5 LUFS）
- **リミッターをつなぐと、ピークは少し上がる**（Chrome の DynamicsCompressor は、おさえた分を自動で持ち上げる）。割れはしない（0dB の手前で止まる）。落とし穴56 に書いた。
  割れを防いでいるのはファイルの大きさ（−3dB）と「同じ音は3つまで」の方。リミッターは、思わぬ重なりの保険
