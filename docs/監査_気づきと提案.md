# 監査：気づきと提案（第35弾・フェーズEで最終整理済み）

第35弾監査（A〜E）で見つけた「バグ未満だがプレイヤーのためになること」の最終リスト。
**これが指示36以降の候補リスト**。バグ修正済みのものは各フェーズの完了報告と各監査台帳にある。

分類：**重要度（高・中・低）×種別（引っかかり＝今の体験の小さな傷／機能提案＝足すと良くなる／設計改善＝方針決めが要る）**

## 上位5件（優先度順・概算規模つき）

### 1. [中・設計改善] kick（出す）を「出入り禁止」にする 【規模：中（1〜2指示）】
出された人は部屋コードを知っているので手で戻れてしまい、切断中に出された人は通知も受け取れず**自動で戻ってしまう**。
学校イベントで「出したのに戻ってくる」は進行役が一番困る気まずさ事故。短時間の出入り禁止リスト＋本人への文言が要る。
→ **プレイヤーのため**：進行役が「出す」を安心して使え、場の秩序を守れる。

### 2. [中・設計改善] 途中退室した人と勝敗の方針を決める 【規模：中（1〜2指示・方針決めから）】
部屋ワードウルフで投票中にウルフ本人が退室→誤処刑→「ウルフの逃げ切ち！勝者＝退室した人」になる（実機確認済み）。
ロジックは一貫しているが「アプリごと逃げた人が勝つ」は納得感に欠ける。不戦敗にするか・表示を添えるか、
**部屋ゲーム全体の方針**として決める（wolfroleでも同種の状況があり得る）。
→ **プレイヤーのため**：残って遊んでいる人の勝負の納得感を守る。

### 3. [中・引っかかり] 手渡しスコアに「きょうの通算」ラベルを付ける 【規模：小（1指示以内）】
「もう一度」の意味が手渡し（通算で続ける）と部屋（リセット）で違い、手渡しスコア画面に通算の明示が無い。
初対面の人たちは「スコアがリセットされてない？」と混乱し得る（学校イベントが最初の本番）。ラベル1つで意図が伝わる。
→ **プレイヤーのため**：初見の人が数字の意味を迷わない。

### 4. [中・引っかかり] 同義ラベルの並走コピーを各1関数に集約する 【規模：小（1指示以内）】
夜の死因（曖昧系）が部屋側・手渡し側に同文コピー、勝敗文言が2〜3か所にコピー。今日は全て一致しているが、
**この構造では既に一度、実プレイに出る誤表示が起きている**（処刑が「襲撃」・修正済み＝再発済みパターン）。
「進行中は曖昧・決着は明示」の2系統は保ち、系統内の重複を集約する。
→ **プレイヤーのため**：将来の変更で「片方だけ直る」誤表示を構造的に防ぐ。

### 5. [低・機能提案] hidden旧モード4つを削除する 【規模：中（1〜2指示・記録の後方互換を確認しながら）】
秒でこれ・手渡し旧クイズ王・旧早押し・旧オークションは`hidden:true`で到達不可のまま、部屋版とロジック・用語・
記録の書き方が並走している（落とし穴1・5の温床）。復活予定が無ければ削除を推奨（記録の互換だけ残す）。
→ **プレイヤーのため**：直接は見えないが、並走起因の誤表示バグの発生源を根から絶つ。

## 6位以下（重要度順）

### 設計改善（方針決めが要る）
- [中] **memberIdと「本人しか知らない入室トークン」の分離** 【規模：大（要設計議論）】：memberIdは部屋内共有IDのため、
  部屋の中の人同士なら以前から枠の成り代わりが可能（見知った仲間内という原則4の前提に寄りかかっている）。
  露出境界（部屋の外に出ない）はD-14で全数確認済みなので急がないが、根本対策はトークン分離。
  → 知らない人が紛れる会場でも秘密が守られる土台。
- [低] 長時間「切断中」のままの枠を名簿から自動で畳むか（入り直し猶予とのトレードオフ）【小〜中】
  → 名簿が実態と合い、進行役が迷わない。
- [低] 30人へ上限を広げる場合は配役バランスの大人数調整が前提（docs/運用メモ.mdに条件記録済み）【中】
  → 1クラス1部屋の需要に、薄いゲームを出さずに応えられる。

### 引っかかり（小さな傷・いずれも規模：小）
- [中] スキップ設定の人にも開始の3-2-1の「はじまるよ」を一拍出す（共有の合図は消さない）
  → 全員で一斉に始まる感覚が、演出を切っている人にも届く。
- [中] 「部屋」ボタンの在室確認中に「確認中…」の小さな表示を出す
  → 遅い回線で「押せてない？」と連打しなくなる。
- [低] 復帰した元ホストに「進行役は◯◯さんに移りました」を明示（d03・hostChanged放送は既にある）
  → 「バグ？」と不安にさせない。
- [低] 観戦中（途中入室）の案内に「次のゲームから遊べます」を全ゲーム統一で出す（d10）
  → 待たされている人が、待てば遊べると分かる。
- [低] 集計のカウントアップ中は「…」を出す等、途中の数字を確定と誤読させない
  → 張り詰めた集計の瞬間の誤解を防ぐ。
- [低] AI待ち表示がゲームを跨いで数秒残る（endGameでrenderAILockを1回呼ぶ・1行）
  → 新しいゲームの頭に前のゲームの表示が出ない。
- [低] rtBombLiveの決着演出が「見ていない試合」で1回出る（leaveで1行リセット）
  → 見ていない爆発に驚かない。
- [低] 協力版bombの大画面が全員同値の行で並ぶ（チーム1本のバー＋「誰が切ったか」へ）
  → 大画面を見る人が進み具合を正しく読める。
- [低] 復帰時に名前の再入力が要る（memberId非保持設計とのトレード。名前だけ端末に覚える案）
  → リロード後の復帰が1タップ減る。
- [低] サバイバル決着後の「新しい勝負をはじめる」を1タップに
  → 盛り上がった流れのまま次の勝負に入れる。

### 機能提案・運用
- [低] 決着時のDB書き込み失敗にリトライ（recordedを戻して次のpushで再試行）【小】
  → 障害時でも思い出（対戦履歴）が残る確率が上がる。
- [低] `/healthz`にコミットハッシュを載せる【小】：サーバー側だけの変更をpushした時、
  本番反映をcurl一発で確認できるようになる（第35弾D/Eのpush確認で公開ファイルの目印が無く困った実体験から）。
  → 直接はプレイヤー向けでないが、安全なリリース確認＝事故の少ない本番につながる。
