# 監査：画面一覧（第35弾フェーズC）

体験品質監査の台帳。**行の一覧は`tests/inventory.js`の`SCREEN_IDS`・`OVERLAY_IDS`（`public/index.html`から自動抽出）が正**で、
全画面ぶんの行があることを`tests/room-paths.js`が機械照合する（画面を足したら行を足さないとテストが赤くなる）。

## 列の意味（指示35C第2部の観点）

1. **テーマ**：カセット別テーマの適用と、切り替え時の残留（落とし穴3）
2. **演出**：スキップ可能か・fx.js共通部品か・長さ・「責める時は静かに」
3. **秘密**：手渡し/見せる瞬間・大画面・再接続直後に見えてはいけない情報が映らないか（落とし穴6）
4. **文言**：初見で読める説明か・ボタンが結果を正しく予告するか・誤字/表記ゆれ
5. **操作**：連打/二重送信・誤タップ配置・小画面崩れ・戻る/リロードの明らかな破綻

セルは `未` / `OK(日付)` / `バグ→修正済` / `バグ→気づき` / `—`（その観点が該当しない）。

- ※テ … テーマは1本の共通経路（`goTo`→`applyGameTheme`・全遷移で全テーマclassを付け外し）のため、
  仕組みの機械照合＋代表実機で全画面ぶんを充足：①手書き4リスト（`THEME_FREE_SCREENS`等）⊆正本`SCREEN_IDS`の
  照合テスト新設（room-paths・typo模擬で赤確認）②既存jsdom4点（付く／棚で外れる／カセット間で混ざらない／QR参加の逆引き）
  ③実機で棚→人狼（ウィザード・モード・セットアップ全部に夜テーマ＋夜背景）→棚（素に戻る）→爆弾（bombのみ・
  背景色も別テーマの実描画 rgb(8,9,11)≠rgb(12,15,26)）を確認（8/16）。
  オーバーレイは`body:has(.app.theme-◯)`でbodyごと着色される設計（オーバーレイ個別の適用漏れが構造上起きない）

## 発見メモ

- **8/16 UI残骸の横展開（micStatus型の全数調査）——新たな実バグなし**。方法：共有画面ごとに
  「子要素id×display切替の分布」を静的に洗い、切替が片方向しかない要素を残骸候補として1つずつ追跡。
  - `scr-play`（19要素が切替・最大のホットスポット）：ワードウルフ話し合い分岐の隠しリストは
    micStatus修正後で完全。`btnFoul`はリスト外だが親`resultRow`ごと隠れるため実害なし。
    タイマー帯5要素は`setupPlayTimerUI`が**現在の状態から両方向に出し分ける共通関数**でカバー（良い型）
  - `scr-rt-play`／`scr-rt-quiz`／大画面の中身：毎描画でinnerHTMLを書き直す自己リセット型＝構造的に残骸が出ない
  - 大画面`bigBoard`（爆弾専用の横棒グラフ）：隠し場所が4箇所に分散する「分岐ごと個別隠し」の型だが、
    ディスパッチャがWW/人狼系に入る前に必ず隠すため全経路カバー済み（現状穴なし・分散自体は将来リスク）
  - オーバーレイ：`bombWireOverlay`・`correctPickerOverlay`は入場リセットあり、`rtBombOverlay`・`dfModOverlay`は
    leave関数で閉じる（Bの掃引済み）。`quizResultOverlay`はhidden旧モード専用（プレイヤー到達不可）＋2.5秒自動クローズ
  - **唯一の発見**：`aiWaitNote`（「🤖AIが考えています…」）はAI生成中にゲームを中断して別ゲームへ移ると、
    裏のfetchが終わるまでの数秒間、次のゲームの画面に残る（`renderAILock`は`try/finally`＋件数管理で
    恒久スタックは無い＝自己回復する）。気づき[低]に記録（1行修正案つき）
