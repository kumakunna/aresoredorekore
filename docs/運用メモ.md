# 運用メモ（学校オフラインイベント向け）

実際にイベントで回す人のための、設計判断の背景つきメモ。

## 部屋の人数上限：20人（第35弾D・2026-08-18決定）

- `room:join`のサーバー門で**プレイヤー20人まで**（21人目は「満員です（20人まで）」）。
  既存メンバーの復帰（リロード・スリープ復帰）は満員でも締め出さない。大画面表示は人数に数えない。
  数えるのは**接続中のプレイヤー数**（切断中の枠は数えない。8/18のQR不具合の教訓：枠数で数えると入れ替わりの多い部屋で新規が誤って弾かれる）
- **理由**：技術上は30人でも余裕（実測：開始→30人への秘密配布20ms・30人同時操作66ms・放送はKB級）だが、
  話し合い・投票が成立する**体験の実用域**が15〜20人まで。30人では投票候補が29ボタン並び、
  「全員済み」待ちが間延びし、**配役もwolf3固定でゲームが薄くなる**（技術的に「詰め込める」ことと
  「遊べる」ことは別・プレイヤーファースト）
- **1クラス（30〜40人）を受ける時**：1部屋に詰めず「**2部屋＋大画面2台**」に分ける。
  半分ずつ遊んで入れ替える・2部屋対抗にする等、分割の方が体験が濃い
- **将来上限を広げる場合の前提条件**：配役バランスの大人数調整（`balancedCounts`のwolf数など）を先に行うこと。
  この判断を変える時は、上の実測値と「体験が薄くなる」所見を再評価の出発点にする

## サーバー再起動（pm2 restart）の扱い

- 部屋はメモリ上のため、**再起動で全部屋が消える**（記録DBは残る）。クライアントは落ちず、
  以後の操作は「部屋が見つかりません」系で丁寧に断られ、部屋ボタンの導線は自動的に片付く
- 運用では「再起動＝全部屋リセット・部屋の作り直し」を前提に、**イベント中の再起動は休憩時間に**行う

## 記録（対戦履歴）の書き込み失敗

- DBが書けない状態（ディスク満杯等）でも**ゲームは決着し部屋は壊れない**（進行優先の設計）。
  ただしその試合の記録は失われ、リトライは無い。サーバーログ
  「対戦履歴の保存に失敗しました」が出ていないかをイベント後に確認する

## 文化祭の部屋（指示66-2・2026-10-24）

人がいなくても回る部屋。係（くまくんと先生）は、作る・止める・とばす・隠す・外す・TVの端あわせだけをする。

| すること | どこで |
|---|---|
| 部屋を作る・作り直す | 係のスマホで `/fes?staff=1`（係のアカウントでログイン）→「文化祭の部屋を作る」／「部屋を作り直す」 |
| TV をつなぐ | TV のブラウザで `/fes?tv=1`（作り直しても、TV は自分で新しい部屋に入り直す） |
| 机・壁のポスターの QR | `/fes`（いまの文化祭の部屋へ自動で飛ぶ。作り直しても同じ QR が使える） |
| 係を決める | サーバーの `.env` に `FES_OWNER=くまくんのユーザー名`・`FES_STAFF=先生のユーザー名`（カンマで複数）。**名前はコードにも docs にも書かない** |
| 名前の記録を見る | くまくん（owner）だけ：ログインして `/api/fes/names` |
| 感想を見る | 係の画面の「感想を見る」（くまくんと先生） |

- 名前の記録と感想は**1か月で自動で消える**（起動のたびと1時間ごと）
- 部屋は16人まで。だれもいなくても片付かない（呼び込みの画面で待つ）。消すのは係の作り直しだけ
- 準備OK と「つづける？」で2回つづけて何も押さなかった人は、席が空く（本人には「もう一度入れます」と出る）
- 書体はアプリのサーバーから配る（会場の通信が弱くても字が変わらない）
