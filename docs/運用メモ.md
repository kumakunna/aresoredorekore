# 運用メモ（学校オフラインイベント向け）

実際にイベントで回す人のための、設計判断の背景つきメモ。

## 部屋の人数上限：20人（第35弾D・2026-08-18決定）

- `room:join`のサーバー門で**プレイヤー20人まで**（21人目は「満員です（20人まで）」）。
  既存メンバーの復帰（リロード・スリープ復帰）は満員でも締め出さない。大画面表示は人数に数えない。
  数えるのは**接続中のプレイヤー数**（切断中の枠は数えない。8/18のQR不具合の教訓：枠数で数えると入れ替わりの多い部屋で新規が誤って弾かれる）
- **理由**：技術上は30人でも余裕（実測：開始→30人への秘密配布20ms・30人同時操作66ms・放送はKB級）だが、
  話し合い・投票が成立する**体験の実用域**が15〜20人まで。30人では投票候補が29ボタン並び、
  「全員済み」待ちが間延びし、**配役もwolf3固定でゲームが薄くなる**（技術的に「詰め込める」ことと
  「遊べる」ことは別・プレイヤーファースト）
- **1クラス（30〜40人）を受ける時**：1部屋に詰めず「**2部屋＋大画面2台**」に分ける。
  半分ずつ遊んで入れ替える・2部屋対抗にする等、分割の方が体験が濃い
- **将来上限を広げる場合の前提条件**：配役バランスの大人数調整（`balancedCounts`のwolf数など）を先に行うこと。
  この判断を変える時は、上の実測値と「体験が薄くなる」所見を再評価の出発点にする

## サーバー再起動（pm2 restart）の扱い

- 部屋はメモリ上のため、**再起動で全部屋が消える**（記録DBは残る）。クライアントは落ちず、
  以後の操作は「部屋が見つかりません」系で丁寧に断られ、部屋ボタンの導線は自動的に片付く
- 運用では「再起動＝全部屋リセット・部屋の作り直し」を前提に、**イベント中の再起動は休憩時間に**行う
- **サーバーの再起動（push）は、遊んでいない時だけ。11/13 からは push しない**（くまくん 2026-10-29。push すると本番が作り直される）
- 文化祭の部屋で再起動が起きた時（2026-10-29 から）：
  - 参加者のスマホと TV は「いま部屋を作り直しています。係の人を待ってね」の画面になる（TV は TV のまま）
  - 係の画面は「部屋が消えました。作り直してください」と大きく出る → **係が「作る」を押す**
  - 部屋ができると、待っているスマホと TV は数秒で自動で進む（スマホは入る画面へ・名前は覚えている。むずかしさは選び直す。TV はそのまま TV に）
  - 点と席は消える（新しい部屋なので、全員が新しく入り直す）。ポスターの QR（/fes）はそのまま使える

## 検査のための記録（スマホのエラー・知らせの遅れ）— 11/7 の検査の準備 7・6

| すること | やり方 |
|---|---|
| 入れる | サーバーの `.env` に `PROBE=err,lag`（エラーだけなら `PROBE=err`）→ だれも遊んでいない時に `pm2 restart`。**無ければ何も動かない**（道は 404・端末は何も送らない） |
| 読む | サーバーの中で `node tools/probe-report.js --errors`・`--lag --since 13:00 --until 13:20`（読むだけ）。置き場は `data/probe/` |
| 切る | `.env` の `PROBE` の行を消して `pm2 restart`。**検査が終わったら必ず切る**（入れている間は全部の端末から受け取る） |
| 入るもの | エラーの字・ファイルの道・行・スタックの頭・画面の id・役（スマホ／TV／係）・機種（UA）・版。遅れの ms。**名前・部屋のコード・URL の ? から後ろは入らない** |
| 上限 | 1つの IP から1分に600回・1日のファイル 20MB |
