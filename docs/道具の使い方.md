# 技術構成と道具の使い方

もとは CLAUDE.md の「4. 技術構成」。2026-10-23、使用量を減らすためにここへ移した（**中身は一字も変えずに移しただけ**）。
要点だけは CLAUDE.md に残してある。検証・測定・変異の道具を使う前に、その道具の段落をここで読む（`grep -n 道具の名前 docs/道具の使い方.md`）。
新しい道具を作ったら、ここに1段落足す（落とし穴29）。

## 技術構成

- Node.js + Express + SQLite（`better-sqlite3`）、フロントは基本単一HTML（`public/index.html`）
- テスト可能・再利用可能なロジックは`public/js/`に切り出す（例：`wolf-logic.js`, `bomb-logic.js`）
- リアルタイム同期の土台は`realtime.js`。ゲームごとの進行役は`GAME_DRIVERS`に登録するだけで繋がる形（`wolf-room.js`, `bomb-room.js`など）
- 演出の共通部品は`public/js/fx.js`（`hold`, `flash`, `banner`, `flip`, `countUp`, `stagger`, `fly`, `alive`, `notice`など）。**新しい演出は、ここに追加する形で作る。ゲームごとに個別実装しない**
- 称号システムは`public/js/titles.js`（`STAT_SHAPE`にカウンタ、`CATALOG`にパーツを追加する形）
- 初プレイのチュートリアルは`public/js/tutorial.js`（指示57）。
  **カセットごとに「手順の台本」を渡すだけ**で、ゲーム側にロジックを書かない。
  出すかどうかは `tutAsk`／`tutRun`（index.html）の1か所が全部の門を通る——
  **出す側に条件を書かせない**（良い型1・4）。
  穴は `clip-path`、置き場は `#uiLayerRoot`。**理由は `docs/監査_指示57の門.md` 2節に実測で残してある**
- 絵文字はTwemoji（SVG）に統一済み。新しい絵文字を使う時は `node tools/gen-emoji-list.js --fetch` を実行する
- `npm test`：全テストを1コマンドで実行（`tools/run-tests.js`）。
  **走らせるスイートは `tests/` から導く**（`createRunner` を持つファイル）ので、
  新しいスイートを足せば自動で入る——package.json に書き忘れて静かに走らなくなる形をやめた（落とし穴4）。
  - `npm run test:time` … 遅い順とメモリのピークも出す（**`--jobs 1` に固定**。測る時は並走させない）
  - `npm run test:list` … 走らせる一覧と、単独／並走の別を見るだけ
  - **合否は3つそろって初めて緑**：スイート数（走らせた＝見つけた）・件数（成功＝全部）・終了コード。
    どれか1つでも欠けたら1を返す。**`| grep` を挟んでも判定はすり替わらない**
    （挟んだ瞬間に終了コードが grep のものになる事故を2回踏んだ・落とし穴28）
- **網羅系テストは、個別ケースの列挙ではなく`tests/inventory.js`等のデータ一覧（正本）を回すループ形式で書く**。正本は可能な限りコードから自動導出し（GAME_DRIVERS・index.htmlの画面id等）、監査台帳（`docs/監査_*.md`）とは機械照合でつなぐ。こうすると「ゲームや画面を足したのに検証が追いつかない」が、追加した瞬間にテストの赤で分かる（落とし穴4の恒久対策・第35弾で確立）
- `npm run playthrough`：通しプレイ検証
- **実サーバーでログインが要る検証は `/dev-login`。** `node tools/dev-server.js`
  （または launch.json の `aresore-dev`）で起動し、`http://localhost:3001/dev-login` を
  一度開けば検証用ユーザーのセッションが張れる。**パスワードは要らない・アカウント作成も要らない**
  - **「初めての人」の検証に、この口は使えない**（指示57）。
    検証用ユーザー（`kensho34`）には**遊んだ記録がたまっていく**——
    実際 `bakudan.plays` は **9** だった。しかもサーバー側の stats は単調増加なので、
    **0に戻す道が無い**（`/api/titles` に小さい値を送っても下がらない）。
  - **初回の検証は、別オリジンのゲストで部屋に入る。**
    `http://127.0.0.1:3001/` は `localhost` と `localStorage` が分かれるうえ、
    **部屋はログイン不要**なので、そのままゲスト＝記録ゼロの人になれる。
    進行役だけ `localhost`（`/dev-login` 済み）で立てる。
    ※**手渡しはログインが要る**ので、この手ではゲストの手渡しを検証できない
- **複数端末をつなぐ検証は `node tools/room-bots.js --code ABC123 --n 3 --ready`。**
  部屋は先にブラウザ側（`/dev-login` 済み）で立て、出たコードを渡す
- **2台目のブラウザは、別オリジンで作る**（第45弾で見つけた）。
  同じブラウザの2つ目のタブは `localStorage` を共有するので、
  1人目の memberId を引き継いでしまい**別人になれない**。
  `http://127.0.0.1:3001/` と `http://localhost:3001/` は**別オリジン**なので
  `localStorage` が分かれる——同じ dev-server に、2人の別々の端末としてつながる。
  bot と違って本物のブラウザなので**切断しない**（bot は数十秒で `connected:false` になり、
  「進行役をゆずる」が効かなくなる）。進行役を渡してから開き直す検証は、この形でしかできない
- **「その瞬間、演出が本当に出たか」は `node tools/fx-probe.js bomb coop`**（第47弾）。
  **指示53で False or True にも広げた**——`falsetrue true` / `falsetrue false` /
  `--skip`（演出を出さず結果だけ）。ゲームを足す時は、その `*-room.js` を同じ形で呼ぶ。
  jsdom の上で**本物の進行役（`*-room.js`）を動かし、本物の publicView / privateFor を
  本物の画面へ流して**、出ている最中に `.bomb-boom` などを数える（落とし穴25・10-g）。
  `--big`（大画面の端末として見る）・`--reversed`（秘密が先・部屋の知らせが後＝落とし穴18の順）・
  `--late`（解除中を一度も見ずに決着だけ届く）で、**演出が消える場面を作り分けられる**。
  ブラウザ枠が裏に回っていても正しく数えられるので、落とし穴28に引っかからない
- **大画面の「共通の時計」が本当に配られるかは `node tools/probe-big-clock.js`**（指示55）。
  **`fx-probe` では足りない**——あちらは `publicView` を直接呼ぶので、
  時計を作っている `realtime.js` の `publicSnapshot` を通らない。
  実サーバーを立てて、協力版クイズ解除（人が待つ3分）で `clock` が出ること、
  とくとくクイズ（「次の1文字が出る時刻」）で `clock` が **null** になることを並べる
- **「ルールを読んだか」の鍵が経路で変わるのを見るのは `node tools/probe-rules-key.js`**（第48弾）。
  本物の `realtime.js` を立てて、棚から選ぶ／再戦／強制終了／別モードの各経路で
  部屋の `state.data.modeId` がどうなるかを並べる。端末の鍵は `rtRulesKey()` ＝
  `modeId ?? gameId` なので、**modeId が消える経路では別の記憶になる**
- **ゲーム固有クラスが終了後も `#app` に残るかは `node tools/probe-leftover-class.js [--big]`**（第48弾）。
  `fx-probe.js` と同じく本物の進行役を動かし、ライフ1で `bomb-danger` が付いたあと
  強制終了・ゲーム変更で外れるかを数える
- **`hidden` が本当に効いているかは `node tests/hidden-attr.js`**（第51弾）。
  jsdom では捕まえられない事故なので、**CSSそのものを読む**——理由は落とし穴35。
- **世界の色が近すぎないかは `node tools/color-diff.js`**（指示49）。
  `public/index.html` の**現物**から表を読み、総当たりで ΔE2000 を出す。
  案を採点するのは `node tools/color-palette.js`。
  **ΔE2000 の実装は Sharma らの検証データ9件で先に検算してある**（落とし穴19）
- **世界の色を「1つ足す」時は `node tools/fot-color.js`**（指示53）。
  8色目の案を、通らなければならない門（7色との ΔE2000・地と墨の対・世界の薄墨 7:1・
  つまみの縁・その世界に載せる光の色）に1つずつ当てて、**落ちた項目を数える**。
  `node tools/fot-color.js space` は「**どの色相なら空いているか**」を測る——
  L\*=14 で一周して「門を満たす最小の彩度」を出すので、
  **黒のままでいられる方向**が1回で分かる（純黒は L\* 25 まで明るくしないと通らない）
- **ゲームの規則は、実装の前に回して確かめる。手本は `node tools/fot-preflight.js`**（指示53）。
  設計メモの表と結果表をそのままデータにして、種つき乱数で何万回も回す。
  指示53ではこれで**着手前に3つのズレ**が出た——設計メモの本文と表が食い違っていた／
  終了条件の片方が原理的に到達不可能だった／結果表4通りが実は1つの性質に畳めた。
  **どれも実装してからでは、赤くならないので気づけない**（テストは仕様どおりに通ってしまう）
- **なにそれ・むり（マニアックな問題）が入りうる入口を掃くのは `node tools/tier-scan.js`**（指示58）。
  層を「引く・並べる・受け取る」語が出てくる関数ごとに、門（`QuizBank.allowedTiers` を通る名前）を
  通っているかを出す。`tests/tier-gate.js` の X3 が**同じこれを呼び**、通らないものは理由つきの表と
  両方向で照合する。**なにそれ・むりの入口を足したら、門を通すか、表に理由を書くまで赤い**
- **つぎつぎクイズの答えと別名を人が読む形にするのは `node tools/dump-list-topics.js`**（指示55）。
  `docs/つぎつぎクイズの答えと別名.md` を現物から作り直す。
  別名は981件あってコードでは読み切れないが、
  「この別名は本当に同じものを指すか」は**人が読んで決める**しかない
- **画面に出る日本語を全部集めるのは `tools/ui-text-scan.js`**（指示49 49-5）。
  **層は6つ**——JS（単引用・二重引用・バッククォート）／HTMLの地の文（改行をまたぐ節点も）／
  HTMLの属性／CSSの `content`／サーバーが返す文言／ui-text.js の中の生きている文言。
  `tests/ui-text.js` と `tools/dump-ui-text.js` が**同じこれを呼ぶ**（写さない）。
  `node tools/dump-ui-text.js` が `docs/文言一覧.md` を作り、
  `node tools/triage-ui-text.js` が表記ゆれ・専門用語・誤字の候補を出す
- **大画面の文字が正本§11-5 の下限を満たすかは `node tools/measure-big-screen.js`**（指示55）。
  1280×720 の実ブラウザで27か所を測り、**未達を一覧で出す**。
  下限は 主役96px／数字48px／本文28px（50型を4mから見て ISO 9241-303 の20分角）。
  SELFTEST で測り方が効くことを先に見る。**道具そのものも試す**——
  わざと1つ 20px にして、`.bb-head`・`.bb-name` の2件が拾われることを確かめてある
- **大画面（TV）を、サーバーも bot も立てずに全ゲーム×人数（4/8/16/20・上限で切る。20 は部屋の上限）×同着（1位が1/2/4/6人）で撮って測るのは `node tools/big-lab.js --port 3990 --cdp 9690`**（指示64。`--only 名前の一部`・`--sizes 1280,1920`・`--out 置き場`・`--probe 'JSの式'`＝測ったあとにページで評価して出す）。
  切れ・巻き・小さい字（数字の段は48）・入場の知らせと QR の重なり・**読めない名前（見えている字が3字未満）**を ✖ に数え、名前の省略（…）と opacity で薄めた字は別に出す。
  BGM の拍（`bgm-beat` の明滅）は「落ち着いた」の邪魔に数えない（`tools/big-measure.js` の `走る演出`・census と共有）。
  本物の流れで測るのは `node tools/big-census.js <カセットid> --players N --port 39xx --cdp 96xx`（`--per 3`＝同じ形の測り直しの上限。
  飛ばした数は記録に残る）。鍵は大画面の「形」（`#scr-rt-big` の data-big／data-phase・順位表の形・出ている枠…）で、
  **頼んだ人数で回らなかったら 1 で終わる**。表は `node tools/big-census-report.js`
  本物のページに疑似socket（tests/harness.js から読み出す）で、本物の進行役が作った部屋の知らせ（tools/big-lab-scenes.js）を流す。
  測る式は big-census.js と共有（tools/big-measure.js）、最初に 900px の箱・12px の字・演出の重なりで物差しを自己検査する。出力は `docs/監査_大画面の画像/lab/`
- **全画面が画面に収まるかは `node tools/measure-screens.js`**（指示49 49-2）。
  回し方と、**測り方が効くことを見る自己検査**が入っている。
  `innerHeight` と `clientHeight` は食い違うので、**折り返しの権威は `clientHeight`**
  - **貼らずに自動で回すのは `node tools/measure-screens-run.js`**（指示60 B-6）。
    375×667／375×812 × 文字3段階（保存値 fontScale 85/100/130 で開き直す）で、
    主ボタンが見えるか・はみ出し・**押す的44px未満**（`::before` で広げた押せる範囲も数える）を出す。
    `--settings` で設定の全ページ。先に 900px の箱で測り方が効くことを確かめる
- **Chrome を裏で動かす部品は `tools/cdp.js`**（指示60）。puppeteer を入れずに、Node 24 の組み込み
  WebSocket で CDP を話す。`newDevice()` は **localStorage もクッキーも別の端末**を作る
  （1つの Chrome の中で、進行役・参加者・大画面を別々の人にできる）。**スクショをファイルに残せる**
  （ブラウザ枠のスクショは残せない・枠が裏に回ると止まる）。本番には向けない
- **審査会のデモの流れを実サーバーで通すのは `node tools/demo-walk.js`**（指示60 B-2）。
  検証用サーバーを立ててから流す。進行役（/dev-login）が部屋をつくり、**QRを jsqr で読んで**
  ログインしていない参加者が入り、大画面もつなぎ、爆発の回と解除の回を通して
  `docs/審査会_デモ/` にスクショを置く。`--skip`（参加者をスキップ設定に）・`--noflash`（光を切る）。
  **出た演出の時系列**（黒い幕・💥・帯・祝い・称号の出入り）も出す
- **QRから「終わったあと」まで、手順ごとに3台を同時に撮って測るのは `node tools/flow-walk.js <カセットid> --port 32xx --cdp 95xx --idle 60`**（指示62）。
  進行役375×812（/dev-login）・参加者375×667（ゲスト・QRを jsqr で読んで入る）・大画面1280×720 と bot 2（`tools/room-bots.js --play`、
  ゲームごとの遊び方は `tools/bot-play/<ゲームid>.js`）の4人で、台本は `tools/flow-walk/<カセットid>.js`（9本）。
  手順ごとに押す回数・待ち時間・迷いの材料を `記録.json` に、`一覧.jpg`（`tools/flow-sheet.js`）を
  `docs/監査_審査会の指摘_画像/<id>/`（gitignore）に置く。9本の表は `node tools/flow-report.js`。
  **並べて走らせる時は --port と --cdp をずらす。測る時は1本ずつ**（落とし穴11）。検証用の Chrome は音を消してある（`--mute-audio`）
- **すごろくのミニゲームを bot 無し・全員が人で通すのは `node tools/probe-63-sugoroku-humans.js`**（指示63 門G2）。

- **待合（375×667）の一言と QR は `node tools/probe-63-lobby.js`**、着替えが名簿と大画面に届くかは `probe-63-look.js`、
  出て戻ると同じ人かは `probe-63-return.js`（指示63 門G5・G6・G8）。**QR は撮った画像を jsQR で読む**（画面の SVG ではない）。
  通し直しを別の置き場に取るのは `flow-walk.js <id> --out DIR`、並べて比べるのは `flow-report.js --dir DIR`。
  bot は 3-2-1 の最中に送って断られたら送り直す（`room-bots.js` の送る道1か所）
- **新しい見た目（v2・指示66）**：決まりの正本は `docs/デザインの正本.md` §12。CSS は index.html の「指示66：新しい見た目（v2）」の節

  - **見本データで画面を開くのは `/v2lab`**（`node tools/dev-server.js` のあと `http://localhost:3001/v2lab?scene=fes-lobby&n=6`。
